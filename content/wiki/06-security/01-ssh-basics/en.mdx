## What SSH Does

SSH (Secure Shell) establishes an encrypted connection to another computer. You type commands on your laptop,
They are executed on the server. Everything that passes through the connection is encrypted: passwords, commands, and output.

For a home lab, SSH is the standard way to work. The server sits on a shelf somewhere, and you manage it from your desk.

## Client and Server

Every connection involves two parties:

- The **server** is a service (`sshd`) that runs on the Homelab computer and listens on port 22 by default.
  On Debian and Ubuntu Server, you can install it using the package`openssh-server`—usually right during installation.
- The **client** is the program on`ssh` your laptop. It comes pre-installed on Linux, macOS, and Windows 10/11.

A connection looks like this:

```bash
ssh admin@192.168.1.10
```

The username on the server comes`@` before the address, and the address comes after it. Use this to end`exit` the session.

## Key Pairs Instead of Passwords

A password can be guessed or intercepted. As soon as SSH is accessible from the Internet, bots try to guess it around the clock
common combinations. Keys solve this problem.

A **key pair** consists of two files:

| File | Where it is located | Who is allowed to see them |
| --- | --- | --- |
| Private key, e.g., `~/.ssh/id_ed25519` | only on your laptop | no one but you |
| Public key, e.g., `~/.ssh/id_ed25519.pub` | on any server you want | every |

## known_hosts and Fingerprint

There are keys on the other side, too. Every SSH server has its own **host key**. This is how it proves to you that
that you're actually communicating with your server and not with a device that has inserted itself into the connection.

The first time you connect, you'll see a message like this:

```text
The authenticity of host '192.168.1.10 (192.168.1.10)' can't be established.
ED25519 key fingerprint is SHA256:...
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

The **fingerprint** is a short checksum of the host key. If you want to be precise, compare it with the value,
which the server displays itself (either directly on the device or in your VPS provider's console):

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

If you confirm with `yes`, the client saves the host key in `~/.ssh/known_hosts`. From then on, it checks it every time
Check to see if the key is still the same.

If the host key changes, SSH terminates with a major warning (`REMOTE HOST IDENTIFICATION HAS CHANGED`). The
This happens quite innocently if you've reinstalled the server or if an IP address has been assigned to another device. Just
Then delete the old entry:

```bash
ssh-keygen -R 192.168.1.10
```

If you haven't changed anything, take the warning seriously and don't just connect anyway.

## File Permissions

SSH is strict about file permissions. If the folder or the private key is readable by others, the client will deny the
Key. Here's how to set the correct permissions:

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_ed25519 ~/.ssh/config
```

On the server, the same applies to  `~/.ssh`and `~/.ssh/authorized_keys`.
