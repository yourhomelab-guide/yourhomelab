## What matters

A homelab server runs around the clock, mostly without much to do. So three things count above all:

- **Power consumption at idle.** The computer spends most of its time waiting. Whether it draws 8 or 50 watts while
  doing so makes a noticeable difference over a year. Example calculations are in
  [Costs & power consumption](/en/wiki/costs-power/), and the [power calculator](/en/tools/power-calculator/)
  works out your own numbers.
- **Memory (RAM).** Every container takes up memory. With many services, RAM is more of a bottleneck than computing
  power.
- **Quiet and small.** The device often sits in the hallway, on a shelf or next to the router.

Raw computing power, on the other hand, rarely matters. A current entry-level processor easily handles a password
manager, file sync, monitoring and a reverse proxy.

## The device classes

<Cards>
  <Card title="Mini PC (N100/N150 class)">
    New, compact computers with frugal Intel processors. Low power draw, quiet, x86 like a normal PC. The obvious
    choice for most beginners.
  </Card>
  <Card title="Used business mini PC">
    Retired small-form-factor office computers, such as Lenovo ThinkCentre Tiny, HP EliteDesk/ProDesk Mini or Dell
    OptiPlex Micro. Sturdy, easy to upgrade and often cheap used.
  </Card>
  <Card title="Raspberry Pi">
    Very frugal and small. Uses an ARM processor, so not every Docker image runs on it. Good for a few light services.
  </Card>
  <Card title="NAS">
    Ready-made storage devices with several drive bays, for example from Synology or QNAP. Strong on storage, often
    limited with Docker and shipped with little RAM.
  </Card>
  <Card title="Old desktop PC">
    Costs nothing if you already have it, and offers lots of room for disks. Usually draws considerably more power at
    idle, though.
  </Card>
  <Card title="VPS">
    A rented virtual server in a data center. No hardware at home, fixed IP, but monthly costs and little storage.
  </Card>
</Cards>

## Compared

The values are rough guidelines. Actual consumption depends heavily on the model, the installed disks and the BIOS
settings.

| Device                     | Idle (rough)             | Strengths                             | Weaknesses                               |
| -------------------------- | ------------------------ | ------------------------------------- | ---------------------------------------- |
| Mini PC N100/N150          | about 5–10 W             | Frugal, quiet, new with warranty      | Usually only one RAM slot, little room for disks |
| Used business mini PC      | about 8–15 W             | Sturdy, upgradable, cheap             | Older CPU, no warranty when used         |
| Raspberry Pi               | about 3–5 W              | Very frugal, tiny                     | ARM, SD card as a weak spot              |
| NAS (2–4 bays)             | about 15–40 W with disks | Lots of storage, disk redundancy      | Docker often limited, little RAM         |
| Old desktop PC             | about 30–70 W            | Already there, lots of room           | High power draw, loud                    |
| VPS                        | no power of your own     | Fixed IP, no device at home           | Monthly costs, little storage            |

## Memory

As a rough guide:

- **4 GB** is enough for a handful of light services, such as a reverse proxy, password manager and monitoring.
- **8–16 GB** is a comfortable start for a typical homelab with databases and a file cloud.
- You need **more** for memory-hungry services like photo archives with face recognition, or if you also want to run
  virtual machines, for example with [Proxmox VE](/en/wiki/proxmox-ve/).

When buying, check whether you can add RAM later. Many N100 mini PCs only have a single slot.

## Storage: SSD and hard disks

Install the system on an **SSD**. It's fast, quiet and frugal. An NVMe SSD with 256–512 GB is enough for the
operating system, containers and the data of most services.

For large amounts of data like photos or videos, **hard disks (HDD)** come in. They're cheaper per terabyte but draw
extra power and make noise. A mini PC usually has no room for them; then an external USB enclosure or a separate NAS
helps.

<Callout type="warning" title="Raspberry Pi and SD cards">
SD cards don't cope well with constant writes and can fail without warning. Better run a Pi as a server with an SSD,
via USB or, on the Raspberry Pi 5, through an NVMe adapter.
</Callout>

## ECC memory

**ECC** (error correcting code) is memory that detects and corrects single-bit errors. It's standard in data center
servers. In forums, it's recommended mainly in connection with ZFS and [TrueNAS](/en/wiki/truenas-unraid/).

ECC isn't a requirement to get started. Mini PCs and most desktop systems don't support it at all. If you later plan
a big data store with valuable data, it's worth a look. Good backups matter more than ECC in any case.

## What about the architecture?

Most mini PCs, business computers and desktops use **x86-64** (also called amd64). Practically every Docker image
exists for it. The Raspberry Pi and some cloud servers use **ARM64**. Many well-known projects offer images for both
architectures, but not all. Check the project page beforehand if you go with ARM.

## Recommendation to start

A mini PC of the N100/N150 class or a used business mini PC with 16 GB of RAM and an NVMe SSD is a good, frugal base
for most beginners. If you want to try things out first, an old computer that's lying around anyway or a small VPS
will do too. Which model fits your plan is covered in [Cloud, hybrid or local?](/en/wiki/cloud-hybrid-local/),
and the concrete choice in the guide [Choosing hardware](/en/setup/choosing-hardware/). Which devices others
actually use is shown under [Homelabs](/en/homelabs/).
