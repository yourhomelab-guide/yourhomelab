## Symptom

The browser shows a warning like `NET::ERR_CERT_AUTHORITY_INVALID`. Instead of a real certificate, Traefik serves its
fallback certificate **TRAEFIK DEFAULT CERT**; Caddy and Nginx Proxy Manager (NPM) report an error when requesting it.
The proxy's log says something like:

```text
Unable to obtain ACME certificate for domains "app.example.com":
... acme: error: 400 :: urn:ietf:params:acme:error:connection :: Timeout during connect (likely firewall problem)
```

```text
acme: error: 429 :: urn:ietf:params:acme:error:rateLimited :: too many certificates already issued ...
```

## Why this happens

Before Let's Encrypt issues a certificate, it checks that you own the domain. For this, Let's Encrypt connects to your
server from the internet (the challenge). On this site, Traefik uses the TLS challenge over port 443; Caddy and NPM
usually use the HTTP challenge over port 80. If this connection fails, there's no certificate. The background is in
[TLS & certificates](/en/wiki/tls-certificates/).

## Causes

1. **DNS doesn't point to your server.** The A record is missing, has a typo or points to an old IP.
2. **A wrong AAAA record.** If there's an IPv6 record, Let's Encrypt prefers to try over IPv6. If it points nowhere,
   the challenge fails even though IPv4 works.
3. **Port 80/443 isn't forwarded on the router**, or a firewall blocks it.
4. **No public IPv4 (CGNAT, DS-Lite).** Then nobody from outside reaches your router; see
   [CGNAT & DS-Lite](/en/wiki/cgnat-ds-lite/).
5. **Rate limit.** After too many attempts or certificates, Let's Encrypt blocks you for a while, typically after many
   restarts with a deleted `acme.json`.
6. **acme.json has the wrong permissions (Traefik).** Traefik refuses the file if it isn't `600`.
7. **A typo in the configuration**, such as a cert resolver name other than `le`, or a missing email address.

## Checking

**Read the logs.** The error message usually names the cause directly:

```bash
cd __ROOT__/traefik
docker compose logs traefik | grep -i -E "acme|certificate"
```

For Caddy and NPM, run `docker compose logs` in the respective stack folder.

**Check DNS.** Both addresses must belong to your connection. `dig` is in the `bind9-dnsutils` package:

```bash
dig +short A app.__DOMAIN__
dig +short AAAA app.__DOMAIN__
curl -4 ifconfig.me; echo
```

The IPv4 from `dig` must match the one from `curl`.

**Check reachability from outside.** The easiest way is to open `http://app.__DOMAIN__` on your phone over the mobile
network (Wi-Fi off). If nothing arrives at all, it's down to port forwarding, the firewall or CGNAT.

**Permissions of acme.json (Traefik):**

```bash
ls -l __DATA(traefik)__/letsencrypt/acme.json
```

Correct is `-rw-------`. Otherwise the log says something like `permissions 644 for /letsencrypt/acme.json are too open, please use 600`.

## Fix

- **DNS:** correct the A and AAAA records at your domain provider. If you don't have working IPv6, delete the AAAA
  record. Changes take a few minutes to a few hours, depending on the TTL. See the guide [Domain & DNS](/en/setup/domain-dns/).
- **Port forwarding:** forward ports 80 and 443 (TCP) on the router to your server's IP; see
  [Port forwarding](/en/wiki/port-forwarding/). Check with `sudo ufw status` that both ports are allowed.
- **CGNAT:** the challenge over port 80/443 can't succeed. Use a [tunnel](/en/wiki/tunnels/) or the DNS challenge.
  With the DNS challenge, your proxy proves the domain through a record at the DNS provider, with no open ports at all.
  That needs an API key from your provider; see the [Traefik docs on ACME](https://doc.traefik.io/traefik/https/acme/).
- **acme.json:**

  ```bash
  chmod 600 __DATA(traefik)__/letsencrypt/acme.json
  cd __ROOT__/traefik && docker compose restart traefik
  ```

- **Rate limit:** wait. The message usually says from when it works again. Don't keep deleting the `acme.json`,
  otherwise you request new certificates every time. The limits are in the
  [Let's Encrypt docs](https://letsencrypt.org/docs/rate-limits/).

## Testing with the staging environment

While you're still experimenting, use Let's Encrypt's test environment. It has much more generous limits but only
issues certificates the browser doesn't trust. For Traefik, add this under `command:`:

```yaml
      - --certificatesresolvers.le.acme.caserver=https://acme-staging-v02.api.letsencrypt.org/directory
```

Once everything works, remove the line again, clear the stored test certificates and restart:

```bash
cd __ROOT__/traefik
docker compose down
: > __DATA(traefik)__/letsencrypt/acme.json
docker compose up -d
```

Caddy has the global option `acme_ca` for this; see the [Caddy docs](https://caddyserver.com/docs/caddyfile/options).
