## Symptom

The browser displays a warning such as `NET::ERR_CERT_AUTHORITY_INVALID`. Instead of a real certificate, Traefik provides
its replacement certificate, **TRAEFIK DEFAULT CERT**, Caddy and Nginx Proxy Manager (NPM) report an error when
Request. The proxy log might show something like this:

```text
Unable to obtain ACME certificate for domains "app.example.com":
... acme: error: 400 :: urn:ietf:params:acme:error:connection :: Timeout during connect (likely firewall problem)
```

```text
acme: error: 429 :: urn:ietf:params:acme:error:rateLimited :: too many certificates already issued ...
```

## Why This Happens

Before Let's Encrypt issues a certificate, it verifies that you own the domain. To do this, Let's Encrypt connects
from the Internet to your server (challenge). On this page, Traefik uses the TLS challenge over port 443,
Caddy and NPM typically use the HTTP challenge over port 80. If this connection fails, there is no certificate.
Background information can be found in "[TLS & Certificates](/en/wiki/tls-certificates/)."

## Causes

1. **The DNS is not pointing to your server.** The A record is missing, contains a typo, or is pointing to an old IP address.
2. **An incorrect AAAA record.** If there is an IPv6 entry, Let's Encrypt will try to connect via IPv6 first. If it shows
   into thin air; the challenge fails, even though IPv4 works.
3. **Port 80/443 is not forwarded on the router,** or a firewall is blocking it.
4. **No public IPv4 address (CGNAT, DS-Lite).** In that case, no one from outside can access your router; see
   [CGNAT & DS-Lite](/en/wiki/cgnat-ds-lite/).
5. **Rate Limit.** After too many attempts or certificates, Let's Encrypt locks you out for a while—typically after many
   Restarts with the `acme.json`. deleted.
6. **acme.json has incorrect permissions (Traefik).** Traefik rejects the file if it does not have`600` the correct permissions.
7. **Typos in the configuration**, such as a Cert Resolver name that isn't `le`correct or a missing email address.

## Check

**Read the logs.** The error message usually states the cause directly:

```bash
cd __ROOT__/traefik
docker compose logs traefik | grep -i -E "acme|certificate"
```

For Caddy and NPM, `docker compose logs`in the respective stack folder.

**Check the DNS.** Both addresses must belong to your connection.  Included`dig` in the package`dnsutils`:

```bash
dig +short A app.__DOMAIN__
dig +short AAAA app.__DOMAIN__
curl -4 ifconfig.me; echo
```

The IPv4 address from  `dig`must match`curl` the one from .

**Check if the location is accessible from outside.** The easiest way is to use your cell phone on the cellular network (Wi-Fi off) to access the address
`http://app.__DOMAIN__` Access it. If nothing comes through, it's due to port forwarding, a firewall, or CGNAT.

**Permissions for acme.json (Traefik):**

```bash
ls -l __DATA(traefik)__/letsencrypt/acme.json
```

That's correct`-rw-------`. Otherwise, the log will show something like `permissions 644 for /letsencrypt/acme.json are too open, please use 600`.

## Solution

- **DNS:** Correct the A and AAAA records with your domain provider. If IPv6 isn't working, delete the
  AAAA record. Depending on the TTL, changes may take anywhere from a few minutes to a few hours. See the [Domain & DNS](/en/setup/domain-dns/) Guide.
- **Port Forwarding:** Forward ports 80 and 443 (TCP) on the router to your server's IP address; see
  [Port authorization](/en/wiki/port-forwarding/). Use the command `sudo ufw status`to check whether both ports are allowed.
- **CGNAT:** The challenge via ports 80/443 won't work. Use a [tunnel](/en/wiki/tunnels/) or
  The DNS Challenge. In the DNS Challenge, your proxy verifies the domain through an entry with the DNS provider, completely
  without open ports. This requires an API key from your provider; see
  [Traefik documentation on ACME](https://doc.traefik.io/traefik/https/acme/).
- **acme.json:**

  ```bash
  chmod 600 __DATA(traefik)__/letsencrypt/acme.json
  cd __ROOT__/traefik && docker compose restart traefik
  ```

- **Rate Limit:** Just wait. The message usually says when it will be available again. Don't`acme.json` keep deleting it over and over again,
  Otherwise, you'll have to get new certificates every time. The limits are listed in the
  [Let's Encrypt Documentation](https://letsencrypt.org/docs/rate-limits/).

## Testing in the staging environment

As long as you're still experimenting, use the Let's Encrypt test environment. It has much more generous limits and provides
but only certificates that the browser doesn't trust. For Traefik, add the following under `command:`:

```yaml
      - --certificatesresolvers.le.acme.caserver=https://acme-staging-v02.api.letsencrypt.org/directory
```

If everything works, delete the line, clear the saved test certificates, and restart:

```bash
cd __ROOT__/traefik
docker compose down
: > __DATA(traefik)__/letsencrypt/acme.json
docker compose up -d
```

Caddy has a global option for this`acme_ca`; see [the Caddy documentation](https://caddyserver.com/docs/caddyfile/options).
