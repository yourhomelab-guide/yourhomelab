## Symptom

Instead of `Up`, `docker compose ps` shows one of these states, and the service isn't reachable:

```text
NAME        IMAGE              STATUS
myapp       myapp:latest       Restarting (1) 8 seconds ago
myapp-db    postgres:18        Up 2 minutes (unhealthy)
```

Because of `restart: unless-stopped`, Docker restarts a crashed container again and again. The waiting time gets
longer each time. The number in brackets is the exit code of the last run.

## First: the log

```bash
cd __ROOT__/myapp
docker compose logs --tail 50 <service>
```

`myapp` stands for your stack, `<service>` for the service name from the `compose.yaml`. Look for the first error line.
The following causes are sorted by how often they occur.

## Causes and fixes

### Missing or wrong variable in the .env

The log says, for example:

```text
Error: Database is uninitialized and superuser password is not specified.
```

On startup, Compose also warns:

```text
WARN[0000] The "POSTGRES_PASSWORD" variable is not set. Defaulting to a blank string.
```

Check that the `.env` is in the stack folder and contains all variables the `compose.yaml` uses. `docker compose
config` shows the values filled in. Watch for typos in the variable name, and for values with special characters like
`$` or `#`, which belong in single quotes. More under [.env files](/en/wiki/env-files/). The
[Compose explainer](/en/tools/compose-explainer/) lists which variables a `compose.yaml` expects from the `.env`.
After changing the `.env`:

```bash
docker compose up -d
```

`restart` isn't enough, because it doesn't pick up the new values.

### Wrong image or wrong architecture

```text
exec /usr/local/bin/docker-entrypoint.sh: exec format error
```

The image is built for a different processor architecture, for example `amd64`, while your server is a Raspberry Pi
with `arm64`. Compare:

```bash
uname -m
docker image inspect --format '{{.Architecture}}' <image>
```

`x86_64` corresponds to `amd64`, `aarch64` to `arm64`. Look on Docker Hub or in the project's docs for an image or a
tag for your architecture. See also [Images & tags](/en/wiki/images-tags/).

### Database not ready yet

The app starts faster than its database and gives up:

```text
Connection refused ... could not connect to server
```

Often this resolves itself after one or two restarts. It's cleaner to give the database a healthcheck that the app
waits for:

```yaml
services:
  app:
    depends_on:
      db:
        condition: service_healthy
  db:
    image: postgres:18
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U $${POSTGRES_USER}"]
      interval: 10s
      retries: 5
```

The double `$$` makes sure the variable is only evaluated inside the container. For MariaDB, the official image comes
with the script `healthcheck.sh`, for example `test: ["CMD", "healthcheck.sh", "--connect", "--innodb_initialized"]`.

### Healthcheck fails

`(unhealthy)` means: the container is running, but its built-in test says something is wrong. Docker therefore does
**not** restart it. However, dependent services with `condition: service_healthy` then don't start, and Traefik doesn't
send traffic to it. To see what the test reports:

```bash
docker inspect --format '{{json .State.Health}}' <container>
```

### Out of memory (OOM)

The kernel kills the process when memory runs out (out of memory, OOM). Typical is exit code `137` with no error
message in the log.

```bash
docker inspect --format '{{.State.OOMKilled}} {{.State.ExitCode}}' <container>
sudo dmesg -T | grep -i -E "out of memory|oom-kill"
```

If that shows `true` or an OOM message, give the service more RAM, remove or raise a `mem_limit` that's set, or stop
other services. `docker stats` shows how much RAM your containers actually use right now.

### No write permission

`Permission denied` in the log? Then continue with [Permission denied](/en/wiki/permission-denied/).

### After an update

If a database no longer starts after an update, see [Database won't start after an update](/en/wiki/database-version/).
For apps, it helps to search the release notes for breaking changes or to temporarily put the old tag back.

## Stopping the loop

While you investigate, you can stop the container so it doesn't keep filling the log:

```bash
docker compose stop <service>
```
