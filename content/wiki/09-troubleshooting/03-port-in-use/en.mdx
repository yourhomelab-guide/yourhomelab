## Symptom

`docker compose up -d` aborts, and the container stays in the `Created` state. Depending on the Docker version, the
message looks something like this:

```text
Error response from daemon: driver failed programming external connectivity on endpoint pihole:
Bind for 0.0.0.0:53 failed: port is already allocated
```

```text
Error response from daemon: failed to bind port 0.0.0.0:80/tcp:
listen tcp4 0.0.0.0:80: bind: address already in use
```

The number after the colon is the port in use on the host.

## Why this happens

A port on the host can only be used by **one** program at a time. With `ports: - "80:80"`, the container asks Docker
to forward the host's port 80 to it. If another program or container is already listening there, this fails.
[IP, ports & NAT](/en/wiki/ip-ports-nat/) explains more about ports.

## Causes

1. **Another container uses the port.** For example two stacks that both use `8080:8080`, or an old container that's
   still running.
2. **Port 80 or 443: a web server on the host.** An Apache or nginx installed earlier, or a second reverse proxy.
3. **Port 53: systemd-resolved.** On Ubuntu, the local DNS service listens on `127.0.0.53:53`. That clashes with DNS
   services like Pi-hole or AdGuard Home.
4. **The same port appears twice in the `compose.yaml`.**

## Check

Who's using the port? Replace `80` with your port:

```bash
sudo ss -tulpn | grep ':80 '
```

The last column names the program, for example `users:(("nginx",pid=812,fd=6))`. If it says `docker-proxy`, it's a
container. This shows which one:

```bash
docker ps --filter publish=80
```

Whether a web server runs as a system service:

```bash
systemctl status apache2 nginx
```

## Solution

### Another container

Stop the old container, or give the new one a different host port. The port on the host is on the left, the one in the
container on the right. You only change the left one:

```yaml
ports:
  - "8081:8080"
```

Behind a reverse proxy, web services usually don't need `ports:` at all. The proxy reaches the container through the
`__NETWORK__` network. Then the conflict disappears completely. The [Compose explainer](/en/tools/compose-explainer/)
shows you which ports a `compose.yaml` you've taken over publishes and which address they're bound to.

### Old web server on port 80/443

If you no longer need it, stop and disable it:

```bash
sudo systemctl disable --now apache2
# or
sudo systemctl disable --now nginx
```

Afterwards you can uninstall it with `sudo apt remove apache2` or `sudo apt remove nginx`.

### Port 53 and systemd-resolved

<Os is="ubuntu">

On Ubuntu Server, systemd-resolved always runs and takes `127.0.0.53:53`. So for a DNS service like AdGuard Home, you
have to turn the stub off.

</Os>

<Os is="debian">

On Debian, systemd-resolved usually isn't installed at all. Check with `systemctl is-active systemd-resolved`. If it
doesn't say `active`, that's not the cause, and you can skip this section.

</Os>

You only turn off the local DNS stub. The server's name resolution keeps working afterwards through the DNS servers
from your network.

```bash
sudo mkdir -p /etc/systemd/resolved.conf.d
printf '[Resolve]\nDNSStubListener=no\n' | sudo tee /etc/systemd/resolved.conf.d/no-stub.conf
sudo ln -sf /run/systemd/resolve/resolv.conf /etc/resolv.conf
sudo systemctl restart systemd-resolved
```

Afterwards, check with `sudo ss -tulpn | grep ':53 '` that the port is free, and with `ping -c1 debian.org` that name
resolution still works.

### Binding to a specific IP

If the server has several IP addresses, a service can also listen on just one of them:

```yaml
ports:
  - "__SERVER_IP__:53:53/udp"
```

## Remember the firewall

If you use a new port that should be reachable from outside, you may have to allow it in UFW. Careful: ports published
by Docker bypass UFW. Details are in the guide [Firewall with UFW](/en/setup/firewall-ufw/).
