## Symptom

The browser shows one of these errors:

```text
404 page not found
Bad Gateway
Gateway Timeout
```

The message already tells you a lot:

| Message | Meaning |
| --- | --- |
| `404 page not found` (Traefik) | No rule matches the address. Traefik doesn't know the service at all. |
| `502 Bad Gateway` | The proxy knows the service but gets no answer from the container. |
| `504 Gateway Timeout` | The proxy tries but doesn't get through. Often a network problem. |

[Reverse proxy explained](/en/wiki/reverse-proxy-explained/) explains more about the proxy's role.

## Causes

1. **The container isn't running.** It crashed or is stuck in a [restart loop](/en/wiki/restart-loop/).
2. **The container isn't on the `__NETWORK__` network.** The proxy can only reach containers it shares a network with.
3. **Wrong port.** The proxy talks to a port the app doesn't listen on.
4. **`traefik.enable=true` is missing (Traefik).** On this site, Traefik ignores all containers without this label.
5. **Host rule or DNS doesn't match.** A typo in `Host(...)`, or the subdomain doesn't point to the server.
6. **The container is `unhealthy` (Traefik).** Traefik doesn't forward to containers whose health check fails.
7. **NPM: wrong forward host or port.**

## Check

**Is the container running?**

```bash
cd __ROOT__/myapp
docker compose ps
```

**Is it on the proxy network?** This output must include both the proxy and your container:

```bash
docker network inspect __NETWORK__ --format '{{range .Containers}}{{.Name}} {{end}}'
```

**Which port does the app listen on?** That's in the image's docs. This also gives a hint:

```bash
docker image inspect --format '{{json .Config.ExposedPorts}}' <image>
```

**Is the container reachable from the proxy network?** A throwaway container on the same network asks directly. Fill
in the container name and port:

```bash
docker run --rm --network __NETWORK__ curlimages/curl -sI http://myapp:8080
```

If an answer comes back with `HTTP/1.1 200` or a redirect, network and port are right. Then it's the proxy
configuration.

**What does the proxy say?**

```bash
cd __ROOT__/traefik
docker compose logs --tail 100 traefik | grep -i -E "error|myapp"
```

**DNS:** `dig +short myapp.__DOMAIN__` must return your server's IP.

## Solution

### Add the network

The service the proxy should reach needs the external network:

```yaml
services:
  myapp:
    networks:
      - __NETWORK__

networks:
  __NETWORK__:
    external: true
```

The [Compose explainer](/en/tools/compose-explainer/) shows you which networks a service is on and whether a
network is included as `external`.

If the container is on several networks, for example also on an internal network to the database, tell Traefik which
one to use. Otherwise it may pick an IP it can't reach, and you get `504`:

```yaml
labels:
  - traefik.docker.network=__NETWORK__
```

### Specify the port (Traefik)

If the image exposes several ports or none, Traefik doesn't know which one to use. Specify it. This means the port
**inside** the container, not a port from `ports:`:

```yaml
labels:
  - traefik.enable=true
  - traefik.http.routers.myapp.rule=Host(`myapp.__DOMAIN__`)
  - traefik.http.routers.myapp.entrypoints=websecure
  - traefik.http.routers.myapp.tls.certresolver=le
  - traefik.http.services.myapp.loadbalancer.server.port=8080
```

The [proxy configuration](/en/tools/proxy-config/) tool generates the right labels for your service.
After changing labels:

```bash
cd __ROOT__/myapp
docker compose up -d
```

### Nginx Proxy Manager

In the proxy host:

- **Forward Hostname / IP:** the container name, for example `myapp`. Not `localhost`, because that would be the NPM
  container itself.
- **Forward Port:** the port inside the container, not the mapped host port.
- **Scheme:** usually `http`. Only `https` if the app itself speaks TLS.

NPM and the service both have to be on the `__NETWORK__` network.

### Caddy

In the Caddyfile, the target is also given as the container name and internal port:

```text
myapp.__DOMAIN__ {
    reverse_proxy myapp:8080
}
```

Reload after a change: `docker compose restart caddy` in Caddy's stack folder.
