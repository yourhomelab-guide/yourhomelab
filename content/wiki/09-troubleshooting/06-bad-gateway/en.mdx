## Symptom

The browser displays one of these errors:

```text
404 page not found
Bad Gateway
Gateway Timeout
```

The headline alone gives away a lot:

| Announcement | Meaning |
| --- | --- |
| `404 page not found` (Traefik) | No rule matches the address. Traefik doesn't even recognize the service. |
| `502 Bad Gateway` | The proxy recognizes the service but does not receive a response from the container. |
| `504 Gateway Timeout` | The proxy tries, but can't get through. This is often a network problem. |

["Reverse Proxy](/en/wiki/reverse-proxy-explained/) Explained[" provides](/en/wiki/reverse-proxy-explained/) more [information](/en/wiki/reverse-proxy-explained/) on the role of a proxy.

## Causes

1. **The container isn't running.** It has crashed or is stuck in a [restart loop](/en/wiki/restart-loop/).
2. **The container is not on the network`__NETWORK__`.** The proxy can only reach containers with which it has a
   The network shares.
3. **Incorrect port.** The proxy is accessing a port that the app is not listening on.
4. **`traefik.enable=true` is missing (Traefik).** Traefik ignores all containers on this page that do not have this label.
5. **The host rule or DNS settings are incorrect. There is** a typo in `Host(...)`, or the subdomain does not point to the server.
6. **The container is (`unhealthy`Traefik).** Traefik does not forward traffic to containers whose health check fails.
7. **NPM: Incorrect forward host or port.**

## Check

**Is the container running?**

```bash
cd __ROOT__/myapp
docker compose ps
```

**Is it stuck in the proxy network?** This output must include both the proxy and your container:

```bash
docker network inspect __NETWORK__ --format '{{range .Containers}}{{.Name}} {{end}}'
```

**On which port does the app listen?** That information is in the image's documentation. There's also a note that says:

```bash
docker image inspect --format '{{json .Config.ExposedPorts}}' <image>
```

**Is the container accessible from the proxy network?** A disposable container on the same network checks directly.
Enter the container name and port:

```bash
docker run --rm --network __NETWORK__ curlimages/curl -sI http://myapp:8080
```

If you receive a response or`HTTP/1.1 200` a redirect, the network and port are correct. In that case, the problem lies with the
Proxy Configuration.

**What does the proxy say?**

```bash
cd __ROOT__/traefik
docker compose logs --tail 100 traefik | grep -i -E "error|myapp"
```

**DNS:**  `dig +short myapp.__DOMAIN__`Must provide your server's IP address.

## Solution

### Add to Network

The service that the proxy is supposed to access requires the external network:

```yaml
services:
  myapp:
    networks:
      - __NETWORK__

networks:
  __NETWORK__:
    external: true
```

The [Compose](/en/werkzeuge/compose-erklaerer/) [Explainer](/en/werkzeuge/compose-erklaerer/) shows you which networks a service is connected to and whether a network is integrated`external`.

If the container is connected to multiple networks—for example, also to an internal network for the database—tell Traefik which one
It should use that one. Otherwise, it might choose an IP address it can't reach, and you'll get`504`:

```yaml
labels:
  - traefik.docker.network=__NETWORK__
```

### Specify the port (Traefik)

If the image exposes multiple ports or none at all, Traefik won't know which one to use. Specify it. This means
the port **in** the container, not a port from `ports:`:

```yaml
labels:
  - traefik.enable=true
  - traefik.http.routers.myapp.rule=Host(`myapp.__DOMAIN__`)
  - traefik.http.routers.myapp.entrypoints=websecure
  - traefik.http.routers.myapp.tls.certresolver=le
  - traefik.http.services.myapp.loadbalancer.server.port=8080
```

The [Proxy Configuration](/en/werkzeuge/proxy-konfiguration/) tool generates the appropriate labels for your service.
After changes to labels:

```bash
cd __ROOT__/myapp
docker compose up -d
```

### Nginx Proxy Manager

The following applies to the proxy host:

- **Forward Hostname / IP:** the container name, for example `myapp`. Not `localhost`, because that would be the NPM container
  yourself.
- **Forward Port:** the port in the container, not the mapped host port.
- **Scheme:** usually `http`. Only`https` if the app itself supports TLS.

Both the NPM and the service must be `__NETWORK__`connected to the network.

### Caddy

In the Caddyfile, the destination is specified in exactly the same way as the container name and internal port:

```text
myapp.__DOMAIN__ {
    reverse_proxy myapp:8080
}
```

Reload after making a change:  `docker compose restart caddy`in Caddy's Stack folder.
