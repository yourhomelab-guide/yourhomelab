## What is Proxmox VE?

Proxmox Virtual Environment (PVE for short) is a **hypervisor**: an operating system whose job is to run other
systems. You install Proxmox directly on the hardware and create virtual computers in it. Each of them behaves like
a server of its own.

Proxmox is based on Debian, open source and free to use. You manage it through a web interface (on port `8006` by
default). The company behind it sells optional subscriptions with support and a particularly well-tested update
channel. Without a subscription, you use the "no-subscription" repository and get a notice at login that there's no
valid subscription. That's normal for a homelab.

## VMs and LXC containers

Proxmox knows two kinds of guests:

<Cards>
  <Card title="Virtual machine (VM)">
    A completely simulated computer with its own kernel (based on KVM/QEMU). Any operating system runs in it: Debian, Ubuntu, Windows, Home Assistant OS. Strong separation from the host.
  </Card>
  <Card title="LXC container">
    A lightweight Linux system that shares the kernel with the Proxmox host. Starts in seconds and needs little RAM, but is less strongly isolated.
  </Card>
</Cards>

[VMs or containers?](/en/wiki/vms-or-containers/) explains the difference in more detail.

## Why Proxmox?

- **Trying things without risk.** Create a new VM, test, delete it again. Your main system stays untouched.
- **Snapshots.** Before an upgrade, you freeze a VM's state. If something goes wrong, you jump back with one click.
  (How well that works depends on the storage type, such as ZFS or LVM-thin.)
- **Backups built in.** Proxmox backs up whole VMs and containers on a schedule, to a local disk, a NAS or a
  Proxmox Backup Server.
- **Several systems on one box.** For example a VM for Docker, one for Home Assistant and a small container for
  Pi-hole.

## Backups with Proxmox Backup Server

[Proxmox Backup Server](https://pbs.proxmox.com/docs/) (PBS) is a separate product, also free. It stores backups
**deduplicated**: blocks that haven't changed are only stored once. That makes daily backups fast, and they take up
little space. PBS can also encrypt and mirror backups to a second PBS.

Ideally, PBS runs on a **different device** than Proxmox itself. A backup on the same disk doesn't protect against a
disk failure.

<Callout title="A VM backup doesn't replace a file backup">
A backup of the whole VM is handy for a quick restore. For individual files and an off-site backup, a tool like
borgmatic inside the VM is worth adding. See [Backup strategies](/en/wiki/backup-strategies/).
</Callout>

## Docker: preferably in a VM

Technically, Docker can also run in an LXC container, and many people do that successfully. Still, we recommend, and
so does the [Proxmox documentation](https://pve.proxmox.com/wiki/Linux_Container), running Docker in a **VM**. The
reasons:

- **Containers in a container.** Docker in LXC means nested containers on a shared kernel. That requires relaxing
  security features (the "nesting" option), and more edge cases come up.
- **Host updates can interfere.** Because LXC shares the kernel with Proxmox, a Proxmox update can change how Docker
  behaves in the container. In a VM, Docker has its own kernel.
- **Better separation.** If a service is compromised, a VM separates it from the host much more strongly.

The price of a VM is a bit more RAM and disk space. For a Docker VM, 2 CPU cores and 4 GB of RAM are often enough to
start. Install Debian or Ubuntu in it and then follow the normal [guides](/en/setup/installing-the-os/)
as if the VM were a server of its own.

## Who is Proxmox worth it for?

Proxmox is an extra layer you have to understand and maintain: storage, network bridges, host updates. For a first
server with a few Docker services, you don't need it. Then [bare-metal Linux](/en/wiki/bare-metal-linux/) is
simpler.

Proxmox is worth it if you

- want to run several operating systems side by side (for example Home Assistant OS next to Docker, see
  [Home Assistant](/en/setup/home-assistant/)),
- like to experiment and value snapshots,
- have enough RAM, roughly from 16 GB.

How Proxmox, bare metal and NAS systems fit into the picture together with Docker Compose is shown in
[Operating models at a glance](/en/wiki/operating-models/).
