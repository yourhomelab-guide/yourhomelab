## What is a NAS operating system?

A NAS (network attached storage) is data storage on the network. A NAS operating system turns a computer with
several disks into exactly that kind of device: it combines the disks into one storage pool, protects against the
failure of individual disks and shares folders on the network, for example via SMB for Windows and macOS or via NFS
for Linux. Everything is set up through a web interface.

The two best-known systems for self-built NAS boxes are **TrueNAS** and **Unraid**. Today, both can also run
containers and VMs, which makes them more than pure storage.

## TrueNAS

TrueNAS comes from iXsystems. The free, open-source version is called **TrueNAS Community Edition** (formerly
"TrueNAS SCALE") and is based on Debian Linux. The older, FreeBSD-based variant TrueNAS CORE is no longer being
developed.

At its heart is **ZFS**, a file system with built-in disk pooling:

- **Checksums for all data.** ZFS detects when a disk silently returns wrong data ("bit rot") and repairs it from
  the redundancy.
- **Snapshots.** A frozen state of a dataset that takes up hardly any space. Useful against accidental deletion and
  ransomware.
- **RAIDZ.** Several disks form a pool that survives the failure of one (RAIDZ1), two (RAIDZ2) or three (RAIDZ3)
  disks.
- **Replication.** Snapshots can be transferred efficiently to a second ZFS system, for example as a backup.

ZFS is robust but not very flexible. Disks should be the same size, and expanding a pool later is limited. Newer
versions can expand a RAIDZ pool by single disks; earlier, that wasn't possible at all. So plan the size of your
storage from the start. ZFS uses free RAM as a read cache, so more RAM helps noticeably.

**Apps:** TrueNAS comes with an app catalog. Since version 24.10, apps run with Docker. You can also add services of
your own as Compose YAML.

## Unraid

Unraid from Lime Technology is **commercial**. It boots from a USB stick the license is tied to and runs entirely in
RAM. You buy the license once. There are several tiers, graded by the number of drives. Depending on the tier,
updates are included for a limited time (optionally renewable afterwards) or for life. The current terms are on the
[Unraid website](https://unraid.net/pricing).

What makes it special is the **Unraid array**:

- **Disks of different sizes** can be mixed. The parity disk only has to be at least as large as the largest data
  disk.
- **Each data disk has its own file system.** If more disks fail than parity covers, only the data on the broken
  disks is lost, not everything.
- **Expandable one disk at a time.** You add another disk, done.
- **Power-saving.** Disks that aren't needed right now can spin down.

The downside: writing is slower, because every change also updates parity, and reading is as fast as a single disk.
That's why you usually use a fast SSD "pool" as a cache and for apps. Newer versions also support ZFS pools.

**Apps:** Unraid has its own Docker interface. With the "Community Applications" plugin, you install hundreds of
ready-made templates with a click. Docker Compose isn't built in, but can be added with a community plugin. VMs run
as well.

## Compared

| | TrueNAS Community Edition | Unraid |
| --- | --- | --- |
| **Cost** | Free, open source | Paid license |
| **Storage** | ZFS, disks of equal size | Array with mixed disks, optionally ZFS |
| **Expanding** | Limited, better plan ahead | Easy, disk by disk |
| **Data safety** | Very high (checksums, self-healing) | Good, array without self-healing |
| **Speed** | High | Array rather slow, SSD cache helps |
| **Good for** | Important data, performance | Media collections, growing storage |

## And Docker as on this site?

The guides on this site assume a normal Linux with Docker Compose. Much of it works on TrueNAS and Unraid, but not
everything one to one: these systems manage Docker through their own interface, paths are different, and changes to
the operating system itself (packages, firewall) aren't intended.

A popular middle ground: the NAS only takes care of storage and shares, and the services run in a
**VM with Debian or Ubuntu**, either on the NAS itself or on a second computer. There you can follow the guides step
by step.

<Callout title="RAID is not a backup">
Parity and RAIDZ protect against a disk failure, not against accidental deletion, ransomware or a fire. A NAS still
needs a backup to another device, ideally off-site too. See [Backup strategies](/en/wiki/backup-strategies/).
</Callout>
