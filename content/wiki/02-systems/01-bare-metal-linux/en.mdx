## What does "bare metal" mean?

"Bare metal" means the operating system runs **directly on the hardware**, without a virtualization layer in
between. So you install a perfectly normal Linux on your mini PC or old laptop, just like on a desktop computer, only
without a graphical interface.

On this Linux, you then install Docker. Each service runs in its own container. So Docker takes care of separating
the services, not a hypervisor.

## Why this path?

For getting started, bare-metal Linux has many advantages:

- **Few moving parts.** One system, one package manager, one place for logs. If something doesn't work, you look in
  exactly one place.
- **Full performance.** No layer that takes a cut of RAM or CPU. That counts on small hardware with 8 or 16 GB of RAM.
- **A huge knowledge base.** Almost every guide on the web assumes Debian or Ubuntu. You'll quickly find error
  messages with a search engine.
- **Easy to transfer.** What you learn here (SSH, users, firewall, Docker), you'll also need later on a VPS or in a
  VM under Proxmox.

Docker already brings the most important property of a VM: services are separated from each other and can be
started, stopped and updated individually. For most homelabs, that's entirely enough.

## Which distribution?

A distribution is a ready-made bundle of Linux kernel, programs and package management. Two are a good fit for a
server:

| | Debian | Ubuntu Server |
| --- | --- | --- |
| **Character** | Lean, conservative, very stable | Somewhat newer packages, more preinstalled |
| **Support** | About three years per release, plus long-term support (LTS) by volunteers | LTS releases get five years of standard updates |
| **New releases** | About every two years | LTS every two years (April, even year) |
| **Maker** | Community project | Canonical (a company) |

Both are a good choice, and all commands on this site work on both. With Ubuntu, always take an **LTS release**
(long-term support), not an interim release. If you can't decide: Debian.

Where the two differ, for example with networking or the SSH service, the guides show both ways. Set your system
under "My setup", and you'll only see the commands that fit your server.

<Callout title="Server without a desktop">
Don't install a graphical interface. You manage the server via [SSH](/en/wiki/ssh-basics/) from your
computer. That saves RAM, and there's less software that needs updates.
</Callout>

## What does the setup look like?

If you follow the guides under [Setup](/en/setup/installing-the-os/), your server will end up looking
roughly like this:

- Debian or Ubuntu Server, login only with an SSH key
- Firewall (UFW) and automatic security updates
- Docker with the Compose plugin
- One folder for everything, `/srv/homelab` (`__ROOT__`) by default, with a subfolder per service
- A reverse proxy like Traefik that makes the services reachable under your domain

One folder for everything has a big advantage: your backup only has to cover `__ROOT__`. More under
[Directory structure](/en/wiki/directory-structure/).

## Limits

Bare metal isn't the best choice in every situation:

- **No system snapshots.** Before a big upgrade, you can't back up and roll back the whole server with one click.
  A good [backup](/en/wiki/backup-strategies/) protects your data; in an emergency, you reinstall the
  operating system. With Docker and a tidy folder, though, that's done quickly.
- **One system for everything.** If you want to try something that doesn't run in Docker, for example another
  operating system or Home Assistant OS, you need a VM. Then [Proxmox VE](/en/wiki/proxmox-ve/) is worth a
  look.
- **Many disks.** If your server is mainly data storage with several disks,
  [TrueNAS or Unraid](/en/wiki/truenas-unraid/) take a lot of work off your hands.

You can switch later. Because all services exist as a `compose.yaml` with their data in the same folder, you move
them to a new system with little effort, for example into a VM under Proxmox. How that works step by step is shown in
[Moving to new hardware](/en/setup/moving-hardware/).

Which foundation suits which goal is compared in [Operating models at a glance](/en/wiki/operating-models/).
