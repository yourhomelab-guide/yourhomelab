## Why use `Compose` instead of `docker run`?

You can start a container using  `docker run`and a long list of options. This works, but it has some drawbacks: You have to memorize the command, typos aren't noticed until startup, and if there's an update, you have to repeat it exactly.

Docker Compose flips that around. You write a file **`compose.yaml`**describing how your containers should look. Compose then ensures that the actual state matches that description. The file is human-readable, can be backed up, and versioned. If the server goes down, you restore the folder and restart it with a single command.

A **stack** consists of`compose.yaml` all the associated containers. On this page, each stack is assigned its own folder under `__ROOT__`; see [the directory structure](/en/wiki/directory-structure/).

## An Example with Comments

This is what a stack looks like for [Uptime Kuma](/en/services/uptime-kuma/), a tool that monitors your services. The file is located in `__ROOT__/uptime-kuma/compose.yaml`.

```yaml
services:                             # all containers of this stack
  uptime-kuma:                        # service name, also its DNS name inside the stack
    image: louislam/uptime-kuma:2     # image and tag to run
    container_name: uptime-kuma       # fixed name instead of an auto-generated one
    restart: unless-stopped           # start again after crash or reboot, unless you stopped it
    environment:                      # settings passed to the program
      - TZ=${TZ}
    volumes:                          # persistent data: host path : container path
      - ./data/data:/app/data
    ports:                            # host port : container port
      - "3001:3001"
    networks:
      - __NETWORK__                   # join the shared proxy network

networks:
  __NETWORK__:
    external: true                    # created once with "docker network create", not by this stack
```

An overview of the most important keys:

| Key | Meaning |
| --- | --- |
| `services` | List of containers. You can choose any name you like (here`uptime-kuma`). |
| `image` | Which image is running in which version. See "[Images & Tags"](/en/wiki/images-tags/) for details. |
| `container_name` | Fixed name. Without it, Compose generates a name based on the folder and service, such as `uptime-kuma-uptime-kuma-1`. |
| `restart` | The "restart" rule `unless-stopped`is almost always correct for Homelab services. |
| `environment` | Environment variables used to configure many programs. Secrets belong in the [.env file](/en/wiki/env-files/). |
| `volumes` | Links folders on the server to folders in the container. See [Volumes & Bind Mounts](/en/wiki/volumes-bind-mounts/). |
| `ports` | Makes a port on the container accessible from the server. The server is on the left, and the container is on the right. |
| `networks` | Which Docker networks the container is connected to. See [Docker Networks](/en/wiki/docker-networks/). |

<Callout title="Ports or reverse proxy?">
The example shows both`networks`  and`ports`  so that you know both keys. In practice, you usually only need one of them: With a reverse proxy like Traefik, the service is only accessible within the network  `__NETWORK__`and does not expose a port. Without a proxy, you access it`http://<server-ip>:3001` via . The templates under ["Services"](/en/services/) automatically adapt this to your setup.
</Callout>

Relative paths such as  always refer`./data` to the folder where the  `compose.yaml`is located. That is why all of a service's data is stored alongside its configuration.

Compose reads`${TZ}` variables such as  from a file  `.env`in the same folder. This keeps the  free`compose.yaml` of passwords, so you can share it.

## The Most Important Commands

Run all commands in the stack's folder:

```bash
cd __ROOT__/uptime-kuma
```

| Command | What he does |
| --- | --- |
| `docker compose up -d` | Create a container and start it in the background. After making changes to the file, simply run it again. |
| `docker compose ps` | Displays the containers in the stack and their status. |
| `docker compose logs -f` | Displays the logs in real time. Press Ctrl+C to exit. |
| `docker compose pull` | Downloads newer versions of the images. Then `up -d`, to use them. |
| `docker compose restart` | Restarts the containers without recreating them. |
| `docker compose down` | Stop and delete the containers and the Stack network. Your data in  `./data`will be preserved. |
| `docker compose exec uptime-kuma sh` | Opens a shell in the running container, if the image provides one. |
| `docker compose config` | Checks the file and displays it with the variables inserted. Great for troubleshooting. |

An update to a service looks like this:

```bash
docker compose pull
docker compose up -d
```

Compose only recreates containers whose image or configuration has changed.

## docker compose or docker-compose?

You'll find both spellings in the instructions. The difference:

- **`docker-compose`** The version with a hyphen is the older, standalone Version 1, written in Python. Development on it has been discontinued since 2023.
- **`docker compose`** Including spaces, the current version is 2. It is a plugin from Docker itself and is installed`docker-compose-plugin` with the package.

Always use `docker compose`. Old instructions usually still work if you replace the hyphen with a space. The developers have also simplified the filename:  `compose.yaml`is the current standard, but  `docker-compose.yml`is still recognized.

<Callout title="You no longer need the &quot;version:&quot; line">
Older Compose files begin with  `version: "3.8"`or something similar. The current version of Compose ignores this specification and only displays a warning. You can simply delete that line.
</Callout>
