A homelab server doesn't need a graphical interface. A minimal Linux without a desktop boots faster, needs less RAM and has less software that can bring updates and security holes. Later you'll manage the server comfortably over SSH from your regular computer. All other guides on this site assume **Debian** or **Ubuntu Server**.

<OneWay />

<Callout title="Using a VPS?">
Then you can skip the installation. In your provider's web interface, pick Debian or Ubuntu as the image; often you can add your SSH key right there too. After a minute or two the server is running and you get its IP address. Then jump straight to the step "Connect over SSH". If you only got root access, create your own user in the guide [Users & sudo](/en/setup/users-sudo/).
</Callout>

<Callout title="Using Proxmox?">
Then you install Debian or Ubuntu the same way, just in a VM instead of directly on the hardware. Create the VM in the Proxmox interface and attach the ISO image as a virtual drive; you don't need a USB stick for that. More in [Proxmox VE](/en/wiki/proxmox-ve/) and [Operating models at a glance](/en/wiki/operating-models/).
</Callout>

<Steps>

<Step title="Choose Debian or Ubuntu Server">
Both systems are a good foundation. The commands in the guides work the same on both.

- **Debian 13** is lean, very stable and changes little. A good choice if you want a quiet system.
- **Ubuntu Server LTS** is based on Debian, ships somewhat newer packages and has a very guided installer. LTS stands for Long Term Support: these versions get updates for five years. The current one is Ubuntu 26.04 LTS; 24.04 LTS is still supported.

If you have no preference, go with Debian. Download the matching image from the official site:

- Debian: [debian.org/download](https://www.debian.org/download) (the "netinst" image for amd64; it downloads packages from the internet during installation)
- Ubuntu Server: [ubuntu.com/download/server](https://ubuntu.com/download/server) (the current LTS version)

Set your choice above under **"My setup"**. Wherever Debian and Ubuntu differ, the guides then only show you the matching way.
</Step>

<Step title="Create the installation USB stick">
You need to write the downloaded ISO image to a USB stick. Simply copying it isn't enough; the stick has to become bootable. All data on the stick will be lost.

- **Windows, macOS, Linux**: [balenaEtcher](https://etcher.balena.io/) – choose the image, choose the stick, "Flash".
- **Windows**: alternatively [Rufus](https://rufus.ie/).
- **Linux terminal**: with `dd`. Check very carefully with `lsblk` first which device your stick is, because `dd` overwrites without asking.

```bash
lsblk
sudo dd if=debian-13-amd64-netinst.iso of=/dev/sdX bs=4M status=progress conv=fsync
```

Replace `/dev/sdX` with your stick and the file name with that of your image.
</Step>

<Step title="Boot from the USB stick">
Connect a monitor, a keyboard and a **LAN cable** to the server. With a cable, the installer finds the network right away and you don't have to set up Wi-Fi.

Plug in the USB stick and turn on the computer. Right after powering on, press the key for the boot menu. Which key that is depends on the manufacturer, often `F12`, `F11`, `F10` or `Esc`. Pick the USB stick there.

If the stick doesn't show up, check in the BIOS/UEFI whether booting from USB is allowed. You can leave Secure Boot on; Debian and Ubuntu support it.
</Step>

<Step title="Install the system">
<Os is="debian">

In the start menu, choose **Install** (the text version is perfectly fine). The installer asks, one after another:

1. **Language, location, keyboard**: as you like.
2. **Hostname**: a short name in lowercase, e.g. `homelab`. The server will show up on the network under this name.
3. **Domain name**: leave empty.
4. **Root password**: **leave empty**. Debian then locks the root account, and your regular user automatically gets `sudo` rights. That's how all guides on this site work too.
5. **User and password**: your regular account. Choose a strong password. Enter the user name above under "My setup", then it appears in all commands in the guides.
6. **Partitioning**: "Guided – use entire disk" and "All files in one partition" is the simplest choice to start with. Make sure you pick the right disk if there are several.
7. **Package manager**: pick a mirror near you, leave the proxy empty.

The most important step comes at **Software selection**. Set the checkboxes like this:

- **Debian desktop environment**: off
- all desktops (GNOME, KDE, Xfce …): off
- **SSH server**: on
- **Standard system utilities**: on

Install the GRUB boot loader on the system disk. Then the computer restarts. Remove the USB stick.

<Callout title="Set a root password after all?">
Then your user doesn't get `sudo`. You can fix that later: log in as root (`su -`), then run `apt install sudo` and `usermod -aG sudo __USER__`, and log in again.
</Callout>

</Os>

<Os is="ubuntu">

The Ubuntu Server installer asks, one after another:

1. Choose **language and keyboard**.
2. **Type of installation**: "Ubuntu Server" is enough. The "minimized" variant is even smaller but comes with fewer tools, which you'd then have to install yourself.
3. **Network**: The LAN connection gets an address via DHCP automatically. Leave it like that. You'll set up the static address in the next guide.
4. **Storage**: "Use an entire disk". By default, Ubuntu sets up LVM and often doesn't use all the space for the system. In the summary, check the size of `ubuntu-lv` and set it to the maximum if needed.
5. **Profile**: name, server name (e.g. `homelab`), user name and password. Enter the user name above under "My setup", then it appears in all commands in the guides.
6. **Ubuntu Pro**: "Skip for now". You don't need it for a homelab, and you can activate it for free at any time later.
7. **SSH**: check **Install OpenSSH server**.
8. **Featured server snaps**: select nothing. You'll install Docker cleanly from the official repository later.

After the installation, restart and remove the USB stick.

</Os>
</Step>

<Step title="Log in and find the IP address">
Log in directly on the server with your user. Then find out which IP address it got on your home network:

```bash
ip -br address
```

The line with your network card (e.g. `enp1s0` or `eno1`) shows the address, something like `192.168.1.50/24`. The number after the slash isn't part of the address. Write the address down.
</Step>

<Step title="Update the system">
The installation media is usually a few weeks old already. Get the current updates right away:

```bash
sudo apt update
sudo apt full-upgrade -y
sudo reboot
```
</Step>

<Step title="Connect over SSH">
From now on you no longer need a monitor and keyboard on the server. Open a terminal on your regular computer (on Windows, PowerShell or Windows Terminal, which already include SSH) and connect:

```bash
ssh __USER__@192.168.1.50
```

Replace the address with the one you just found. On the first connection, SSH asks whether you trust the server. Confirm with `yes`. [SSH basics](/en/wiki/ssh-basics/) explains what happens there.

The address you're using right now was assigned by the router via DHCP and can change. That's why in the next guide you give the server a [static IP and a hostname](/en/setup/static-ip-hostname/). After that you replace the password with [SSH keys](/en/setup/ssh-keys/).
</Step>

</Steps>
