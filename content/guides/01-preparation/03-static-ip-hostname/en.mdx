---
title: Fixed IP & Hostname
description: Your server has a fixed IP address on your home network and a descriptive name. This ensures that SSH connections, port forwarding, and DNS entries always point to the correct device.
level: 1
minutes: 15
requires:
  - Linux Server
  - SSH Access
  - Access to the Router Interface
---

Your router automatically assigns addresses on your home network via **DHCP** (Dynamic Host Configuration Protocol). This is convenient, but the address may change after a reboot or a long period of inactivity. This is problematic for a server: port forwarding, DNS entries, and your SSH connection will suddenly point to nowhere. That’s why the server is assigned a static IP address. You can find the basics on this under [IP, Ports & NAT](/en/wiki/ip-ports-nat/).

There are two ways to do this. The recommended method is to set up a **DHCP** **reservation** in the router: The server continues to request an IP address via DHCP but always receives the same address. Everything remains in one place, and the router knows which addresses have been assigned. The alternative is to configure a static IP address directly on the server.

<OneWay />

<Steps>

<Step title="Record the current network data">
Connect to the server via SSH and check the network card, IP address, and MAC address. The MAC address is the network card's unique identifier; the router uses it to recognize your device.

```bash
ip -br address
ip -br link
ip route
```

Make a note of this:

- the name of the network adapter, for example, `enp1s0`
- the current address, e.g., `192.168.1.50/24`
- the MAC address, for example, `aa:bb:cc:dd:ee:ff`
- The gateway from that line`default via 192.168.1.1`—that's your router.
</Step>

<Step title="Recommended: Reserve an IP address on the router">
Open your router's web interface in your browser. The address is usually printed on the bottom of the device. Look for your server (hostname or MAC address) in the list of network devices and enable static assignment.

On a FRITZ!Box, you'll find this under **Home Network → Network**. There, edit the server and enable "Always assign the same IPv4 address to this network device." On other routers, this feature may be called, for example, “DHCP Reservation,” “Static Lease,” or “Address Reservation.”

You can keep the address the server currently has, or choose your own, such as `192.168.1.10`. Then restart the server so that it can reliably obtain the reserved address:

```bash
sudo reboot
```

Once you've changed the address, connect using the new address. You're now done and can proceed directly to the "**Verify Hostname"** step.
</Step>

<Step title="Alternative: Static IP on Debian (ifupdown)">
This is only necessary if you can't or don't want to set up a reservation on your router. In that case, choose an address **outside** your router's DHCP range; otherwise, the router might assign that address to another device as well. You can find the range in your router's DHCP settings.

<Callout type="warning" title="It's best to work directly on the server">
A typo in the network configuration can cause the SSH connection to be disconnected. It's best to perform this step with a monitor and keyboard connected to the server.
</Callout>

Debian manages the network on servers using `ifupdown`. Open the configuration:

```bash
sudo nano /etc/network/interfaces
```

Replace the section for your network interface (the line containing  `inet dhcp`and, if necessary, `allow-hotplug`) with a static configuration. Adjust the network interface, address, and gateway to match your values:

```text
auto enp1s0
iface enp1s0 inet static
    address 192.168.1.10/24
    gateway 192.168.1.1
```

Enter`/etc/resolv.conf` the DNS server here; in most cases, this is also your router:

```text
nameserver 192.168.1.1
```

Then restart the server (`sudo reboot`) and connect using the new address.
</Step>

<Step title="Alternative: Static IP on Ubuntu (netplan)">
Ubuntu Server configures the network using **netplan**. The same rule applies here: Choose an address outside the DHCP range.

The installation created the configuration using cloud-init. To prevent cloud-init from overwriting your changes, disable its network management:

```bash
echo 'network: {config: disabled}' | sudo tee /etc/cloud/cloud.cfg.d/99-disable-network-config.cfg
```

Check which file is located`/etc/netplan/` in  and open it:

```bash
ls /etc/netplan/
sudo nano /etc/netplan/50-cloud-init.yaml
```

Replace the content with a static configuration. Be sure to use spaces for indentation; YAML is strict about this:

```yaml
network:
  version: 2
  ethernets:
    enp1s0:
      dhcp4: false
      addresses:
        - 192.168.1.10/24
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [192.168.1.1]
```

Test the configuration with `netplan try`. If you don't confirm`Enter` the new setting within two minutes using , netplan will revert to the old one. Here's how to avoid locking yourself out:

```bash
sudo netplan try
```

Once the connection is established, confirm by pressing  and`Enter` then connect using the new address.
</Step>

<Step title="Check and Set the Hostname">
The hostname is the name of the server on the network and in your command prompt. It should be short, in lowercase, and without spaces, e.g., `homelab`. You already assigned it during installation. Here's how to check it:

```bash
hostnamectl
```

If you want to change it:

```bash
sudo hostnamectl set-hostname homelab
```

Be sure to enter`/etc/hosts` the new name as well; otherwise, it will display a`sudo` warning that it cannot resolve the name:

```bash
sudo nano /etc/hosts
```

The line containing  must`127.0.1.1` include the new name:

```text
127.0.0.1       localhost
127.0.1.1       homelab
```

Log out and then log back in, and the command prompt will also display the new name.
</Step>

<Step title="Test Connection">
Finally, check to make sure the address, gateway, and name resolution are correct:

```bash
ip -br address
ip route
ping -c 3 debian.org
```

You should see the static IP address, a `default`route through your router, and a response to the ping.

Many routers resolve device names on the home network. This allows you to access the server by name, for example, or`ssh deinname@homelab` with a FRITZ!Box`ssh deinname@homelab.fritz.box`. If that doesn't work, simply use the IP address.

Next, secure your access: [Set up SSH keys](/en/setup/ssh-keys/).
</Step>

</Steps>
