---
title: "Static IP & hostname"
description: "Your server has a fixed address on your home network and a meaningful name. SSH connections, port forwarding and DNS records then always point to the right device."
level: 1
minutes: 15
requires: [Linux server, SSH access, Access to the router interface]
---

Your router hands out addresses on your home network automatically via **DHCP** (Dynamic Host Configuration Protocol). That's convenient, but the address can change after a restart or a longer break. For a server, that's bad: port forwarding, DNS records and your SSH connection suddenly point nowhere. That's why the server gets a fixed address. You'll find the basics under [IP, ports & NAT](/en/wiki/ip-ports-nat/).

There are two ways. The recommended one is a **DHCP reservation** in the router: the server keeps asking via DHCP but always gets the same address. Everything stays in one place, and the router knows which addresses are taken. The alternative is a static configuration directly on the server.

<OneWay />

<Steps>

<Step title="Note the current network details">
Connect to the server over SSH and look at the network card, address and MAC address. The MAC address is the network card's built-in identifier; the router recognizes your device by it.

```bash
ip -br address
ip -br link
ip route
```

Note down:

- the network card's name, e.g. `enp1s0`
- the current address, e.g. `192.168.1.50/24`
- the MAC address, e.g. `aa:bb:cc:dd:ee:ff`
- the gateway from the line `default via 192.168.1.1`; that's your router
</Step>

<Step title="Recommended: reserve the address in the router">
Open your router's interface in the browser. The address is usually printed on the bottom of the device. Look for your server (host name or MAC address) in the list of network devices and turn on the fixed assignment.

On a FRITZ!Box, you'll find this under **Home Network → Network**. Edit the server there and turn on "Always assign this network device the same IPv4 address". On other routers, the feature is called "DHCP reservation", "static lease" or "address reservation", for example.

You can keep the address the server has right now or choose your own, such as `192.168.1.10`. Enter it as the server IP under "My setup"; then it appears in all further commands. Then restart the server so it's sure to get the reserved address:

```bash
sudo reboot
```

If you changed the address, connect to the new address afterwards. That's it, and you can continue directly with the step **Check and set the hostname**.
</Step>

<Step title="Alternative: static IP on the server">
Only needed if you can't or don't want to set up a reservation in the router. Then choose an address **outside** your router's DHCP range, otherwise the router might also hand it out to another device. You'll find the range in the router's DHCP settings.

<Callout type="warning" title="Ideally, work directly at the server">
A typo in the network configuration can cut the SSH connection. Ideally, do this step with a monitor and keyboard at the server.
</Callout>

How this works depends on the system. You'll see the way for the operating system from "My setup".

<Os is="debian">

On servers, Debian manages the network with `ifupdown`. Open the configuration:

```bash
sudo nano /etc/network/interfaces
```

Replace your network card's block (the line with `inet dhcp` and possibly `allow-hotplug`) with a static configuration. Adjust the network card, address and gateway to your values:

```text
auto enp1s0
iface enp1s0 inet static
    address __SERVER_IP__/24
    gateway 192.168.1.1
```

Enter the DNS server in `/etc/resolv.conf`; usually that's your router as well:

```text
nameserver 192.168.1.1
```

Then restart the server (`sudo reboot`) and connect to the new address.

</Os>

<Os is="ubuntu">

Ubuntu Server configures the network with **netplan**. The installation created the configuration through cloud-init. So that cloud-init doesn't overwrite your changes again, turn off its network management:

```bash
echo 'network: {config: disabled}' | sudo tee /etc/cloud/cloud.cfg.d/99-disable-network-config.cfg
```

Check which file is in `/etc/netplan/` and open it:

```bash
ls /etc/netplan/
sudo nano /etc/netplan/50-cloud-init.yaml
```

Replace the content with a static configuration. Watch the indentation with spaces; YAML is strict about it:

```yaml
network:
  version: 2
  ethernets:
    enp1s0:
      dhcp4: false
      addresses:
        - __SERVER_IP__/24
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [192.168.1.1]
```

Only root may read the file, otherwise netplan warns:

```bash
sudo chmod 600 /etc/netplan/50-cloud-init.yaml
```

Test the configuration with `netplan try`. If you don't confirm the new setting with `Enter` within two minutes, netplan restores the old one. That way you can't lock yourself out:

```bash
sudo netplan try
```

When the connection works, confirm with `Enter` and then connect to the new address.

</Os>
</Step>

<Step title="Check and set the hostname">
The hostname is the server's name on the network and in your prompt. Short, lowercase, without spaces, e.g. `homelab`. You already set it during installation. To check it:

```bash
hostnamectl
```

If you want to change it:

```bash
sudo hostnamectl set-hostname homelab
```

Also enter the new name in `/etc/hosts`, otherwise `sudo` warns that it can't resolve the name:

```bash
sudo nano /etc/hosts
```

The line with `127.0.1.1` must contain the new name:

```text
127.0.0.1       localhost
127.0.1.1       homelab
```

Log out and back in once; then the prompt shows the new name too.
</Step>

<Step title="Test the connection">
Finally, check that address, gateway and name resolution are right:

```bash
ip -br address
ip route
ping -c 3 debian.org
```

You should see the fixed address, a `default` route through your router and replies to the ping.

Many routers resolve device names on the home network. Then you can also reach the server by name, e.g. `ssh __USER__@homelab`, or `ssh __USER__@homelab.fritz.box` on a FRITZ!Box. If that doesn't work, simply use the IP address.

Next, you secure access: [Setting up SSH keys](/en/setup/ssh-keys/).
</Step>

</Steps>
