---
title: "VPN with WireGuard"
description: "In the end, your phone or laptop connects to your home network via WireGuard on the go. You manage access in wg-easy and set up new devices with a QR code."
level: 2
minutes: 30
requires: [Docker Compose, Domain or DynDNS, Port forwarding on the router]
---

A VPN (virtual private network) builds an encrypted tunnel from your device to your home. You're then on your home network as if you were sitting on the sofa, and you reach all services without putting them on the internet. Only a single UDP port is open to the outside, and WireGuard only answers devices with a matching key there. The background is under [VPN](/en/wiki/vpn/).

[WireGuard](https://www.wireguard.com/) is a modern, fast VPN protocol built right into the Linux kernel. This guide uses [wg-easy](https://wg-easy.github.io/wg-easy/): it brings WireGuard in a container, plus a web interface where you create devices and hand them out with a QR code.

<Callout title="Alternatives">
- **Router VPN:** many routers can do WireGuard themselves, the FRITZ!Box for example since FRITZ!OS 7.50. Then you don't need anything on the server. Check there first.
- **Tailscale:** builds on WireGuard and works without port forwarding, even behind CGNAT and DS-Lite. Coordination runs through Tailscale's servers. Details under [Access methods compared](/en/wiki/access-methods-compared/).
- **Plain WireGuard:** without a web interface, configured by hand. Worth it if you want to understand what happens behind the scenes.
</Callout>

<Callout type="warning" title="Not with CGNAT or DS-Lite">
For your phone to reach the server, your connection needs a public IPv4 address. The guide [Domain & DNS](/en/setup/domain-dns/) shows how to check. Without a public IPv4, use Tailscale.
</Callout>

<Steps>

<Step title="Create the folder">
Like every stack, wg-easy gets its own folder under `__ROOT__`. The WireGuard configuration with all keys ends up in `__DATA(wg-easy)__`.

```bash
mkdir -p __ROOT__/wg-easy __DATA(wg-easy)__/wireguard
cd __ROOT__/wg-easy
```
</Step>

<Step title="Write compose.yaml">
Create the `compose.yaml` file. It follows the [official template](https://github.com/wg-easy/wg-easy/blob/master/docker-compose.yml), but stores the data in your data folder. wg-easy doesn't join the proxy network; it gets a network of its own.

```yaml
services:
  wg-easy:
    image: ghcr.io/wg-easy/wg-easy:15
    container_name: wg-easy
    restart: unless-stopped
    environment:
      # Allow the web UI over plain HTTP. Only safe because it is bound to the LAN below.
      - INSECURE=true
    networks:
      wg:
        ipv4_address: 10.42.42.42
        ipv6_address: fdcc:ad94:bacf:61a3::2a
    volumes:
      - __DATA(wg-easy)__/wireguard:/etc/wireguard
      - /lib/modules:/lib/modules:ro
    ports:
      # WireGuard itself, forwarded by the router
      - "51820:51820/udp"
      # Web UI, reachable from the home network only. Use your server's LAN IP.
      - "__SERVER_IP__:51821:51821/tcp"
    cap_add:
      - NET_ADMIN
      - SYS_MODULE
    sysctls:
      - net.ipv4.ip_forward=1
      - net.ipv4.conf.all.src_valid_mark=1
      - net.ipv6.conf.all.disable_ipv6=0
      - net.ipv6.conf.all.forwarding=1
      - net.ipv6.conf.default.forwarding=1

networks:
  wg:
    driver: bridge
    enable_ipv6: true
    ipam:
      driver: default
      config:
        - subnet: 10.42.42.0/24
        - subnet: fdcc:ad94:bacf:61a3::/64
```

`__SERVER_IP__` is your server's IP on the home network from "My setup". That way the web interface is only reachable from the home network (and later through the VPN). Whoever can use it can issue themselves new access, so it doesn't belong on the internet.

The container needs `NET_ADMIN` and the `sysctls` to create the WireGuard interface and forward packets into the home network.
</Step>

<Step title="Start and set up">
Start the stack and check the log to see whether WireGuard comes up without errors.

```bash
docker compose up -d
docker compose logs -f wg-easy
```

Press `Ctrl+C` to leave the log view. If the container doesn't start cleanly, [Troubleshooting: first steps](/en/wiki/first-steps/) helps. Then open `http://__SERVER_IP__:51821` in the browser. On first access, a wizard walks you through the setup:

1. **Create the admin account.** Use a long password from your password manager.
2. **Host:** the address at which your devices find the server from outside, for example `vpn.__DOMAIN__`. Thanks to the wildcard record, the name already points to your public IP.
3. **Port:** `51820`.

You can leave the remaining settings at their defaults.
</Step>

<Step title="Forward UDP port 51820">
On the router, forward port **51820/UDP** to your server's static IP. Make sure it's UDP; WireGuard doesn't use TCP. Don't forward any ports for the web interface. [Port forwarding](/en/wiki/port-forwarding/) explains how forwarding works.

If you use UFW, allow the port there too:

```bash
sudo ufw allow 51820/udp comment 'WireGuard'
```

Strictly speaking, ports published by Docker bypass the UFW rules. But the rule doesn't hurt and documents which ports are supposed to be open.

If you use Cloudflare as your DNS provider, the record for `vpn.__DOMAIN__` must not be proxied through Cloudflare ("DNS only", gray cloud). The Cloudflare proxy only forwards web traffic, not WireGuard.
</Step>

<Step title="Add a device">
Every device gets its own access with its own key. That way you can block a lost phone individually.

1. Create a new client in wg-easy and give it a meaningful name, such as `phone-anna`.
2. Install the official WireGuard app on the device. It's available for Android, iOS, Windows, macOS and Linux; see [wireguard.com/install](https://www.wireguard.com/install/).
3. **Phone:** in the app, add a tunnel from a QR code and scan the QR code from wg-easy.
4. **Laptop:** download the configuration file in wg-easy and import it into the app.

The configuration contains the device's private key. Don't send it by messenger or email.
</Step>

<Step title="Test the connection">
Turn off Wi-Fi on your phone so it really goes over the mobile network. Activate the tunnel in the WireGuard app and open `http://__SERVER_IP__:51821`. If you see wg-easy's login page, you've arrived home. In wg-easy, the client now also shows transferred data and the latest handshake.

If it doesn't work, check in this order:

- Does `vpn.__DOMAIN__` resolve to your current public IP? (`dig +short vpn.__DOMAIN__`)
- Is the port forwarding set to UDP and the right server IP?
- Does the network you're on right now use the same address range as your home network, for example both `192.168.178.x`? Then your device doesn't know where to send the packets. In that case, change your home network's address range to something less common.
</Step>

<Step title="Optional: only home network traffic through the tunnel">
By default, wg-easy sends **all** of the device's internet traffic through your home (full tunnel). That protects you on untrusted Wi-Fi, but puts load on your upload.

If you only want to send traffic to your home network through the tunnel (split tunnel), enter only your home network and the VPN network under **Allowed IPs** in wg-easy's settings, for example `192.168.1.0/24, 10.8.0.0/24`. The VPN network is listed in the settings under the address ranges. Afterwards, the devices have to load the configuration again. Details are in the [wg-easy documentation](https://wg-easy.github.io/wg-easy/).
</Step>

</Steps>
