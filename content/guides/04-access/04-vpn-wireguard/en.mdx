---
title: VPN with WireGuard
description: Ultimately, your cell phone or laptop connects to your home network via WireGuard while you're on the go. You manage access in wg-easy and set up new devices using a QR code.
level: 2
minutes: 30
requires:
  - Docker Compose
  - Domain or DynDNS
  - Port Forwarding on the Router
---

A VPN (Virtual Private Network) creates an encrypted tunnel from your device to your home. You’re then connected to your home network as if you were sitting on the couch, and you can access all services without exposing them to the internet. Only a single UDP port is open to the outside world, and WireGuard only responds to devices with the correct key. For more details, see the [VPN](/en/wiki/vpn/) section.

[WireGuard](https://www.wireguard.com/) is a modern, fast VPN protocol that's built right into the Linux kernel. This guide uses [wg-easy](https://wg-easy.github.io/wg-easy/): It includes WireGuard in a container along with a web interface where you can create devices and distribute them via QR code.

<Callout title="Alternatives">
- **Router VPN:** Many routers support WireGuard natively; the FRITZ!Box, for example, has supported it since FRITZ!OS 7.50. In that case, you don't need anything on the server. Check there first.
- **Tailscale:** is based on WireGuard and works without port forwarding, even behind CGNAT and DS-Lite. Coordination is handled by Tailscale's servers. For details, see "[Comparison of Access Methods](/en/wiki/access-methods-compared/)."
- **Native WireGuard:** no web interface, manual configuration. It's worth it if you want to understand what's happening behind the scenes.
</Callout>

<Callout type="warning" title="Not with CGNAT or DS-Lite">
For your phone to connect to the server, your connection needs a public IPv4 address. See the [Domain & DNS](/en/setup/domain-dns/) guide for instructions on how to check this. If you don't have a public IPv4 address, use Tailscale.
</Callout>

<Steps>

<Step title="Create a directory">
Like every stack, wg-easy gets its own folder under `__ROOT__`. The WireGuard configuration, including all keys, is stored in `__DATA(wg-easy)__`.

```bash
mkdir -p __ROOT__/wg-easy __DATA(wg-easy)__/wireguard
cd __ROOT__/wg-easy
```
</Step>

<Step title="Write a compose.yaml file">
`compose.yaml`Create the file. It follows the [official template](https://github.com/wg-easy/wg-easy/blob/master/docker-compose.yml) but saves the data in your data folder. wg-easy does not use the proxy network; instead, it has its own.

```yaml
services:
  wg-easy:
    image: ghcr.io/wg-easy/wg-easy:15
    container_name: wg-easy
    restart: unless-stopped
    environment:
      # Allow the web UI over plain HTTP. Only safe because it is bound to the LAN below.
      - INSECURE=true
    networks:
      wg:
        ipv4_address: 10.42.42.42
        ipv6_address: fdcc:ad94:bacf:61a3::2a
    volumes:
      - __DATA(wg-easy)__/wireguard:/etc/wireguard
      - /lib/modules:/lib/modules:ro
    ports:
      # WireGuard itself, forwarded by the router
      - "51820:51820/udp"
      # Web UI, reachable from the home network only. Use your server's LAN IP.
      - "192.168.1.10:51821:51821/tcp"
    cap_add:
      - NET_ADMIN
      - SYS_MODULE
    sysctls:
      - net.ipv4.ip_forward=1
      - net.ipv4.conf.all.src_valid_mark=1
      - net.ipv6.conf.all.disable_ipv6=0
      - net.ipv6.conf.all.forwarding=1
      - net.ipv6.conf.default.forwarding=1

networks:
  wg:
    driver: bridge
    enable_ipv6: true
    ipam:
      driver: default
      config:
        - subnet: 10.42.42.0/24
        - subnet: fdcc:ad94:bacf:61a3::/64
```

Replace  `192.168.1.10`with your server's LAN IP address. This way, the web interface is only accessible on your home network (and later via the VPN). Anyone who can access it can create new accounts, so it shouldn't be exposed to the Internet.

`NET_ADMIN` and the container needs`sysctls` these to create the WireGuard interface and forward packets to the home network.
</Step>

<Step title="Getting Started and Setting Up">
Start the stack and check the log to see if WireGuard starts up without any errors.

```bash
docker compose up -d
docker compose logs -f wg-easy
```

Use  to close`Strg+C` the log window. Then open  `http://192.168.1.10:51821`in your browser. The first time you open it, a wizard will guide you through the setup:

1. **Create an admin account.** Use a long password from your password manager.
2. **Host:** the address that allows your devices to locate the server from the outside, for example`vpn.__DOMAIN__`. Thanks to the wildcard record, the name already points to your public IP address.
3. **Port:** `51820`.

You can leave the remaining settings at their default values.
</Step>

<Step title="Open UDP Port 51820">
In your router, forward port **51820/UDP** to your server's static IP address. Make sure to use UDP—WireGuard does not use TCP. Do not open any ports for the web interface. For instructions on how to open a port, see ["Port Forwarding](/en/wiki/port-forwarding/).["](/en/wiki/port-forwarding/)

If you use UFW, allow the port there as well:

```bash
sudo ufw allow 51820/udp comment 'WireGuard'
```

Strictly speaking, the ports that Docker exposes bypass the UFW rules. However, the rule does no harm and documents which ports should be open.

If you use Cloudflare as your DNS provider, the entry for  must not`vpn.__DOMAIN__` go through Cloudflare (“DNS only,” gray cloud). The Cloudflare proxy only forwards web traffic, not WireGuard.
</Step>

<Step title="Add Device">
Each device gets its own account with its own password. This way, you can lock a lost phone individually.

1. Create a new client in wg-easy and give it a descriptive name, such as `handy-anna`.
2. Install the official WireGuard app on your device. It's available for Android, iOS, Windows, macOS, and Linux; see [wireguard.com/install](https://www.wireguard.com/install/).
3. **Cell phone:** Add a tunnel in the app using a QR code, then scan the QR code from wg-easy.
4. **Laptop:** Download the configuration file in wg-easy and import it into the app.

The configuration contains the device's private key. Do not send it via instant messaging or email.
</Step>

<Step title="Test Connection">
Turn off Wi-Fi on your phone so that it really connects via the cellular network. Activate the tunnel in the WireGuard app and open `http://192.168.1.10:51821`. If you see the wg-easy login page, you’ve made it home. In wg-easy, the client now also displays the data being transferred and the last handshake.

If it doesn't work, check the following one by one:

- Does it resolve to`vpn.__DOMAIN__` your current public IP address? (`dig +short vpn.__DOMAIN__`)
- Is the port open for UDP and set to the correct server IP address?
- Does the network you're currently on use the same address range as your home network—for example, are they both the same`192.168.178.x`? If so, your device won't know where to send the packets. In that case, change your home network's address range to something less common.
</Step>

<Step title="Optional: Only allow home network traffic through the tunnel">
By default, wg-easy routes **all** of the device's internet traffic through your home network (full tunnel). This protects you on public Wi-Fi networks, but it does put a strain on your upload speed.

If you only want to route traffic to your home network through the tunnel (split tunnel), enter only your home network and the VPN network in the "**Allowed IPs**" section of the wg-easy settings, for example`192.168.1.0/24, 10.8.0.0/24`. The VPN network is listed in the settings under "Address Ranges." After that, you’ll need to reload the configuration on your devices. Details can be found in the [wg-easy documentation](https://wg-easy.github.io/wg-easy/).
</Step>

</Steps>
