<Callout title="Traefik or Nginx Proxy Manager?">
[Traefik](/en/setup/reverse-proxy-traefik/) is a bit more complicated at first, but offers more options and automation: the configuration lives as labels right in each service's `compose.yaml`, and middlewares for login protection are easy to put in front. That's why the other guides on this site show Traefik labels.

Nginx Proxy Manager (NPM) is the easier start: you click proxy hosts together in a web interface and get certificates with a checkbox. In return, the configuration lives in a database instead of files. You can switch to Traefik later at any time; your services stay unchanged.
</Callout>

A reverse proxy is the only door to your services: it listens on ports 80 and 443 and decides, based on the name, which container answers. More in [Reverse proxy explained](/en/wiki/reverse-proxy-explained/).

<Steps>

<Step title="Create the proxy network">
NPM and your services sit in a shared Docker network. In it, NPM reaches every container by its name. You create the network once and then use it in every stack.

```bash
docker network create __NETWORK__
```

If you've already created the network, Docker reports an error. You can ignore it.
</Step>

<Step title="Create the folder">
Like every stack, NPM gets its own folder under `__ROOT__`. The database, settings and certificates end up in `__DATA(nginx-proxy-manager)__`.

```bash
mkdir -p __ROOT__/nginx-proxy-manager __DATA(nginx-proxy-manager)__
cd __ROOT__/nginx-proxy-manager
```
</Step>

<Step title="Write compose.yaml and .env">
Create both files in the folder. NPM publishes three ports: 80 and 443 for your services and 81 for the web interface.

<ServiceFiles id="nginx-proxy-manager" />
</Step>

<Step title="Start and log in">
Start the stack and watch the log until no new messages appear. On the first start, NPM creates its database and keys; that can take a minute or two.

```bash
docker compose up -d
docker compose logs -f nginx-proxy-manager
```

If Docker reports on startup that a port is already taken, another service is already running there; see [Port already in use](/en/wiki/port-in-use/). Press `Ctrl+C` to leave the log view. Then open `http://__SERVER_IP__:81` in the browser.

On first access, NPM shows a setup dialog where you create your admin account. There are no default credentials anymore. Use a long, random password from your password manager. Do this step right after starting, while the interface is only reachable from your home network.
</Step>

<Step title="Create your first proxy host">
A **proxy host** connects a name with a container. As an example, this step uses [Uptime Kuma](/en/services/uptime-kuma/), which runs internally on port 3001. The container must sit in the `__NETWORK__` network.

Click "Hosts → Proxy Hosts → Add Proxy Host" and fill in:

| Field | Value |
| --- | --- |
| Domain Names | `status.__DOMAIN__` |
| Scheme | `http` |
| Forward Hostname / IP | `uptime-kuma` |
| Forward Port | `3001` |
| Block Common Exploits | on |
| Websockets Support | on |

For the host name, enter the **container name**, not the server's IP. That works because both containers sit in the same network and Docker resolves the names there. The port is the port **inside the container**, as stated in the service's documentation. So the service itself doesn't need a port mapping of its own in its `compose.yaml`. If the name or port is wrong, NPM answers with "502 Bad Gateway"; see [Bad Gateway](/en/wiki/bad-gateway/).

Many modern web interfaces need websockets for live updates. It doesn't hurt to always turn them on.
</Step>

<Step title="Get a certificate">
Switch to the "SSL" tab in the same dialog:

1. Under "SSL Certificate", choose the option for a new Let's Encrypt certificate.
2. Turn on **Force SSL**. Then NPM redirects every HTTP request to HTTPS.
3. You can turn on **HTTP/2 Support** as well.
4. Accept the Let's Encrypt terms of service if asked, and save.

Let's Encrypt checks over port 80 whether you own the domain. If that fails, usually the DNS record or the port forwarding isn't right yet. Check both in the guide [Domain & DNS](/en/setup/domain-dns/). You'll find more causes under [Certificate missing](/en/wiki/certificate/).

Then open `https://status.__DOMAIN__`. You should see Uptime Kuma with a valid certificate. NPM renews the certificates automatically.
</Step>

<Step title="Keep port 81 off the internet">
The web interface on port 81 controls all your access. It must not be reachable from the internet.

At home, that's usually already the case as long as your router only forwards 80 and 443. But careful: ports that Docker publishes **bypass UFW**. So a rule like `ufw deny 81` doesn't help. It's safer to bind port 81 to a specific address in the `compose.yaml`.

On your home network, bind it to your server's LAN IP:

```yaml
    ports:
      - "80:80"
      - "443:443"
      - "__SERVER_IP__:81:81"
```

On a rented server, bind it to `127.0.0.1` and reach it through an SSH tunnel:

```yaml
      - "127.0.0.1:81:81"
```

```bash
ssh -L 8181:127.0.0.1:81 __USER__@__SERVER_IP__
```

As long as the connection is open, you open the interface on your computer at `http://localhost:8181`. After the change, restart the stack:

```bash
docker compose up -d
```
</Step>

</Steps>

## What's next?

For every further service, you create a proxy host: new subdomain, container name, internal port, certificate. The [proxy config](/en/tools/proxy-config/) tool shows you which values a service outside the catalog needs. You don't need the Traefik labels in other guides on this site with NPM; set Nginx Proxy Manager as your reverse proxy under "My setup" instead.

Include the `__DATA(nginx-proxy-manager)__` folder in your backups regularly. It holds all proxy hosts and certificates. For details on further features such as access lists, see the [official documentation](https://nginxproxymanager.com/guide/).
