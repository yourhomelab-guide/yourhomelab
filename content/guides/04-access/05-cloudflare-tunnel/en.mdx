title: Cloudflare Tunnel
description: Ultimately, a service under your domain will be accessible from the Internet without you having to open a port on your router. This also works behind CGNAT and DS-Lite.

minutes: 20
requires:

With a tunnel, your server establishes an outbound connection to Cloudflare on its own. Requests to your domain first go to Cloudflare and are routed to you through this tunnel. Because the connection goes from the inside out, you don’t need to open any ports or have a public IPv4 address. The article [“Tunnels”](/en/wiki/tunnels/) explains how tunnels work in general.

The program on your side is called `cloudflared`. It runs as a container in the proxy network and accesses your services there by name.

## Pros and Cons

| Advantages | Disadvantages |
| --- | --- |
| No open ports on the router | TLS Ends at Cloudflare: Cloudflare Can View Your Traffic in Plain Text |
| Works behind CGNAT and DS-Lite | You are at the mercy of a U.S. provider and its rules |
| Your home IP address remains hidden | In the free plan, uploads are limited to 100 MB per request |
| Free, no need for your own server | Video streaming (Jellyfin, Plex) is not permitted under the Terms of Service |

For services like a password manager or photo storage, the first drawback is this: You’re entrusting Cloudflare with your data in plain text. If you don’t want that, it’s better to use a [VPN](/en/setup/vpn-wireguard/) for private services and reserve the tunnel only for things that are meant to be public anyway. [A comparison of access methods](/en/wiki/access-methods-compared/) provides an overview.

<Steps>

<Step title="Transfer a domain to Cloudflare">
The tunnel only works with a domain whose DNS is managed by Cloudflare. Create a free account with [Cloudflare](https://dash.cloudflare.com/), add your domain, and enter the two nameservers that Cloudflare provides in your registrar's control panel.

It may take anywhere from a few minutes to several hours for Cloudflare to mark the domain as active. For more information on DNS, see the [Domain & DNS](/en/setup/domain-dns/) guide.
</Step>

<Step title="Create a tunnel">
You manage tunnels in Cloudflare's **Zero Trust dashboard**. The first time you access it, select a plan—the free one is sufficient.

1. In the Zero Trust dashboard, open "Networks → Tunnels" and create a new tunnel of the **Cloudflared** type.
2. Give it a name, such as `homelab`.
3. Select **Docker** as the environment. Cloudflare will show you a `docker run`command.
4. Just copy the long **token** that comes after the period`--token`. You don't need the command itself.

The menu items on Cloudflare change from time to time. The current instructions can be found in the [official documentation](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/get-started/create-remote-tunnel/).
</Step>

<Step title="Create a directory and a .env file">
The token is a secret: whoever has it can run your tunnel. That's why it goes in the `.env`, not the `compose.yaml`.

```bash
mkdir -p __ROOT__/cloudflared
cd __ROOT__/cloudflared
nano .env
chmod 600 .env
```

Contents of`.env`:

```bash
TUNNEL_TOKEN=hier-den-token-einfuegen
```
</Step>

<Step title="Write a compose.yaml file">
`cloudflared` Reads the token from the variable`TUNNEL_TOKEN`. The container is hosted on the proxy network so that it can access your services by container name. It doesn't need any ports because it only connects to the outside world.

```yaml
services:
  cloudflared:
    # Pin a specific version tag once it runs, see hub.docker.com/r/cloudflare/cloudflared
    image: cloudflare/cloudflared:latest
    container_name: cloudflared
    restart: unless-stopped
    command: tunnel --no-autoupdate run
    environment:
      - TUNNEL_TOKEN=${TUNNEL_TOKEN}
    networks:
      - __NETWORK__

networks:
  __NETWORK__:
    external: true
```
</Step>

<Step title="Start and Check">
Start the Stack.  It connects`cloudflared` to Cloudflare immediately.

```bash
docker compose up -d
docker compose logs -f cloudflared
```

After a short while, several lines containing  should appear`Registered tunnel connection` in the log. Type  to stop`Strg+C` the display. In the Zero Trust dashboard, the tunnel now shows as "**Healthy**."
</Step>

<Step title="Publish a service">
Now you'll tell Cloudflare which name corresponds to which service. Open the tunnel in the dashboard and add an entry under "**Public Hostname**" (or "Published application routes," depending on your dashboard version). Here's an example using [Uptime Kuma](/en/services/uptime-kuma/):

| Field | Value |
| --- | --- |
| Subdomain | `status` |
| Domain | `__DOMAIN__` |
| Type | `HTTP` |
| URL | `uptime-kuma:3001` |

In the URL field, enter the **container name** and the port **within the container**. This works because  `cloudflared`and the service `__NETWORK__`are on the same network. Cloudflare creates the appropriate DNS record itself and handles the certificate.

Then open it`https://status.__DOMAIN__`. You should see Uptime Kuma.
</Step>

<Step title="Secure Access">
Everything you post through the tunnel is publicly available on the Internet. The tunnel is not a substitute for logging in.

- Only publish services that have their own, well-designed sign-in process.
- For everything else, set up a login requirement. You can do this directly in Cloudflare using **Access** in the Zero Trust Dashboard (see [the Cloudflare documentation on Access](https://developers.cloudflare.com/cloudflare-one/applications/)), or with a third-party service like [Pocket ID](/en/setup/pocket-id/) or [Tinyauth](/en/setup/tinyauth/).
- Do not expose administrative interfaces such as Portainer or the interface of your reverse proxy.
</Step>

</Steps>

<Callout title="Combining Tunnels and Traefik">
Instead of having each service point to its own container, you can also have the tunnel point to Traefik. Then the labels and middlewares from the other guides will work. But there’s a catch: Without open ports, Traefik can’t obtain a certificate via TLS challenge and will redirect HTTP to HTTPS. So you’ll need to adjust the tunnel’s TLS settings or switch Traefik to DNS challenge mode. This is more for advanced users; the options are described in the [Cloudflare documentation on origin settings](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/configure-tunnels/origin-configuration/).
</Callout>
