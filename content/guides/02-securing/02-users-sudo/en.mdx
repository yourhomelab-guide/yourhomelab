On a Linux system, root may do anything, without asking. One typo as root can wipe the whole system, and an attacker who takes over root has everything at once. That's why you work as a **regular user** day to day and only get admin rights for individual commands with `sudo`. It costs a few extra characters, but makes mistakes rarer and more visible. sudo also logs who ran which command and when.

## Do you need this guide?

That depends on how your server was set up:

<Os is="ubuntu">

- **Installed with the Ubuntu installer:** it always creates a user with sudo rights, and root has no password. You're done. At most, check quickly with `sudo whoami`.
- **Rented server with root only:** many hosting providers deliver servers with root only. Do all the steps.

</Os>

<Os is="debian">

- **Installed without a root password:** if you left the root password empty in the installer, your user automatically gets sudo rights. You're done. At most, check quickly with `sudo whoami`.
- **Installed with a root password:** your user exists but isn't allowed to use sudo. Often sudo isn't even installed. Switch to root with `su -` (the minus matters: only then does the shell find commands like `usermod`) and continue with step 2.
- **Rented server with root only:** many hosting providers deliver servers with root only. Do all the steps.

</Os>

In the examples, the new user is called `__USER__`, as entered in "My setup". Use your own name, lowercase and without spaces, and enter it there.

<Steps>

<Step title="Create the user">
Log in as root and create the user:

```bash
adduser __USER__
```

`adduser` asks for a password and a few optional details like your full name, which you can skip with Enter. Choose a strong password. You won't need it for SSH later, but `sudo` asks for it.
</Step>

<Step title="Install sudo and grant rights">
On Debian, sudo is missing if you set a root password during installation. Install it as root and add the user to the `sudo` group. On Debian and Ubuntu, members of this group may run any command with sudo.

```bash
apt update
apt install sudo
usermod -aG sudo __USER__
```

`-aG` means "append to group". Without the `-a`, the user would be removed from all other groups.
</Step>

<Step title="Copy the SSH key">
If you've stored your key with root so far, copy it to the new user. These commands still run as root:

```bash
mkdir -p /home/__USER__/.ssh
cp /root/.ssh/authorized_keys /home/__USER__/.ssh/
chown -R __USER__:__USER__ /home/__USER__/.ssh
chmod 700 /home/__USER__/.ssh
chmod 600 /home/__USER__/.ssh/authorized_keys
```

Without `chown`, the files belong to root and the SSH server ignores them. If there's no key on the server yet, set it up directly for `__USER__` as described in [Setting up SSH keys](/en/setup/ssh-keys/).
</Step>

<Step title="Test the new user">
Leave the root session open and open a new terminal on your computer:

```bash
ssh __USER__@__SERVER_IP__
```

Then check sudo. Group membership only applies from a new login, so test it in this fresh session:

```bash
sudo whoami
```

After entering your password, `root` must appear. If both work, from now on you only work as `__USER__`. Remember to put `User __USER__` into `~/.ssh/config` on your computer.
</Step>

<Step title="Block root login">
You turn off direct root login over SSH with `PermitRootLogin no`. You'll do that in the next guide, [Hardening SSH](/en/setup/hardening-ssh/).

Optionally, you can also lock root's password. Then root can't log in at the local console either. Ubuntu does this by default.

```bash
sudo passwd -l root
```

<Callout type="warning" title="The downside">
With a locked root password, Debian's rescue mode at boot no longer works, because it asks for the root password. In an emergency, you then need a USB stick with a live system. On a server at home, you can keep the password for that reason, as long as SSH is blocked for root. Undo the lock with `sudo passwd -u root`.
</Callout>
</Step>

</Steps>

## A word about the docker group

Later you'll add your user to the `docker` group so you can use `docker` without sudo. That's convenient, but be aware: anyone who may start containers can also mount the server's entire file system with them. Being a member of `docker` is practically as powerful as root. Only add users you'd also give sudo. More in the guide [Installing Docker](/en/setup/installing-docker/).
