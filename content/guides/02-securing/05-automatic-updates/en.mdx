title: "Automatic updates"
description: "In the end, your server installs operating system security updates by itself every night and reboots at a fixed time when needed."
level: 1
minutes: 10
requires: [Debian or Ubuntu server, User with sudo rights]
---

Most break-ins use holes that were patched long ago. A server that nobody updates for months is therefore a bigger risk than almost any misconfiguration. Security updates from Debian and Ubuntu are designed not to break anything. That's why it pays to install them automatically instead of relying on your discipline.

The tool for this is called **unattended-upgrades**. It runs daily, refreshes the package lists and installs updates from the sources you allow. By default, those are mainly security updates.

<Steps>

<Step title="Install the package">
On Ubuntu it's usually installed already, on Debian often not. The command doesn't hurt either way.

```bash
sudo apt update
sudo apt install unattended-upgrades
```
</Step>

<Step title="Turn on automatic updates">

```bash
sudo dpkg-reconfigure -plow unattended-upgrades
```

Answer **Yes** when asked whether stable updates should be downloaded and installed automatically. This creates the file `/etc/apt/apt.conf.d/20auto-upgrades`. It should look like this:

```text
APT::Periodic::Update-Package-Lists "1";
APT::Periodic::Unattended-Upgrade "1";
```

The `1` means: every day. Which sources exactly get updated is defined in `/etc/apt/apt.conf.d/50unattended-upgrades`. The Debian and Ubuntu defaults are fine to start with.
</Step>

<Step title="Dry run">
A dry run shows whether everything is set up correctly, without installing anything:

```bash
sudo unattended-upgrade --dry-run --debug
```

The output shows the allowed sources and which packages a real run would update. To see when the next run is due:

```bash
systemctl list-timers 'apt-daily*'
```

What was actually installed ends up in `/var/log/unattended-upgrades/unattended-upgrades.log` later.
</Step>

<Step title="Handle reboots">
Some updates, especially new kernels, only take effect after a reboot. If one is needed, the system creates the file `/var/run/reboot-required`. By default, though, unattended-upgrades does **not** reboot.

You have two options: check yourself now and then, or allow an automatic reboot at a quiet time. For the latter, create a file of your own instead of changing the one that ships with the package. That way package updates and your settings don't get in each other's way.

```bash
sudo nano /etc/apt/apt.conf.d/51unattended-upgrades-local
```

```text
Unattended-Upgrade::Automatic-Reboot "true";
Unattended-Upgrade::Automatic-Reboot-Time "04:00";
```

The server then only reboots when an update requires it, at 4 a.m. Your containers come back up by themselves afterwards if they have `restart: unless-stopped` in their `compose.yaml`. All templates on this site do.

To check at any time whether a reboot is pending:

```bash
ls /var/run/reboot-required
```
</Step>

<Step title="Restart services after updates">
Not every update needs a reboot of the whole server. When a library like OpenSSL is updated, it's enough to restart the services that use it. Until then, they keep running with the old version in memory.

The tool **needrestart** finds those services. Ubuntu ships it; on Debian, install it:

```bash
sudo apt install needrestart
```

From now on it reports by itself after `apt upgrade`. You can also run it directly at any time:

```bash
sudo needrestart
```
</Step>

</Steps>

## What doesn't get updated automatically

unattended-upgrades only takes care of operating system packages. Two important things are left out:

- **Your containers.** unattended-upgrades never updates the images in your `compose.yaml` files. A hole in Vaultwarden or Nextcloud stays open until you pull a new image. The easiest way to handle this later is [Dockhand](/en/setup/portainer-dockhand/) with checked automatic updates. If you keep your Compose files in Git, you can optionally use [Renovate](/en/setup/updates-renovate/). [Updates](/en/wiki/updates/) explains the background.
- **Docker itself.** You'll install Docker from Docker's own package repository later. That's not in unattended-upgrades' default list. So install its updates by hand from time to time:

```bash
sudo apt update
sudo apt upgrade
```

A quick look once a month is enough. What matters is that it happens regularly.
