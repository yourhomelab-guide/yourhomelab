---
title: Monitoring with Beszel
description: Beszel shows you your server's CPU, RAM, hard drives, network, and every container—along with their history—in a streamlined web interface. It also sends you a notification if a disk is running out of space or a server stops responding.
level: 1
minutes: 15
requires:
  - Docker Compose
  - Reverse Proxy
services:
  - beszel
---

Without monitoring, you won't notice problems until something stops working. Yet many outages show early warning signs: The hard drive fills up over the course of weeks, a container slowly consumes more and more RAM, or the CPU gets too hot in the summer. [Beszel](https://beszel.dev) makes these trends visible and is very resource-efficient in doing so. You can find more information under [Monitoring](/en/wiki/monitoring/).

Beszel consists of two parts:

- The **Hub** is the web interface. It stores the measurement data and sends alerts. You only need it once.
- The **agent** runs on every server you want to monitor. It measures the values and sends them to the hub. In this guide, it runs on the same server as the hub.

The agent establishes an encrypted **WebSocket** connection (a persistent connection over HTTPS) to the hub on its own. Therefore, you don't need to open a port for it in the firewall.

<Steps>

<Step title="Set Up the Stroke">
Like any other service, the hub gets its own folder under `__ROOT__`. Its data is stored in the subfolder `data/`.

```bash
mkdir -p __ROOT__/beszel
cd __ROOT__/beszel
```

Place  and`compose.yaml`  there`.env`:

<ServiceFiles id="beszel" />

Then start the hub:

```bash
docker compose up -d
```

If you're using Nginx Proxy Manager, enable "WebSockets Support" for the proxy host. Otherwise, the agent won't be able to connect later. Traefik and Caddy automatically forward WebSockets.

<Callout type="warning" title="Do not enable login protection beforehand">
Beszel has its own login process. Do not place Tinyauth or any other Forward-Auth middleware in front of it: The agent connects via the address  `/api/beszel/agent-connect`and cannot log in interactively there. Instead, Beszel supports OAuth on its own, for example with [Pocket ID](/en/setup/pocket-id/) (see [the Beszel documentation](https://beszel.dev/guide/oauth)).
</Callout>
</Step>

<Step title="Create an Admin Account">
Open it in`https://beszel.__DOMAIN__` your browser. The first time you visit the site, create an account using your email address and a password. Choose a long, random password from your password manager. This account will also serve as the administrator account.
</Step>

<Step title="Create a system in the hub">
Click "Add System" in the upper-right corner (or "System hinzufügen" in the German interface). In the dialog box, enter the following:

| Field | Value |
| --- | --- |
| Name | Name of your server, e.g., `homeserver` |
| Host / IP | Your server's IP address, here `__SERVER_IP__` |

Below that, the dialog box displays two values that you'll need for the agent right away:

- **Public Key**: This allows the agent to recognize that it is communicating with your hub.
- **Token**: The agent uses this to log in to the hub.

Leave the dialog open and switch to the terminal.
</Step>

<Step title="Start Agent">
The agent gets its own stack. It runs with `network_mode: host`, meaning directly on the server's network rather than on a Docker network. This is the only way it can see the actual network interfaces. It reads the statistics from your containers via the Docker socket.

```bash
mkdir -p __ROOT__/beszel-agent __DATA(beszel-agent)__
cd __ROOT__/beszel-agent
```

`compose.yaml`:

```yaml
services:
  beszel-agent:
    image: henrygd/beszel-agent:latest
    container_name: beszel-agent
    restart: unless-stopped
    network_mode: host
    volumes:
      - __DATA(beszel-agent)__:/var/lib/beszel-agent
      - /var/run/docker.sock:/var/run/docker.sock:ro
    environment:
      - LISTEN=45876
      - HUB_URL=https://beszel.__DOMAIN__
      - KEY=${KEY}
      - TOKEN=${TOKEN}
```

`.env` (Copy the values from the open dialog; enclose the key in quotation marks because it contains a space):

```bash
KEY="ssh-ed25519 AAAA..."
TOKEN=...
```

```bash
chmod 600 .env
docker compose up -d
docker compose logs -f
```

After a few seconds, the log should show that the WebSocket connection to the hub is established. Use  to stop`Strg+C` the display.
</Step>

<Step title="Check the system">
In the dialog box, click "Add System" or "System hinzufügen." The server will appear in the list. If its entry turns green, data is coming in. If you click on the server, you’ll see usage trends for CPU, RAM, disk, network, and—if available—temperatures, as well as CPU and RAM usage for each individual container.

If the dot remains red, check:

- Is it accessible from`https://beszel.__DOMAIN__` the server itself? Test: `curl -I https://beszel.__DOMAIN__`. Some routers do not forward internal requests back to their own public address (missing NAT loopback). In that case, a local DNS entry that points the domain to the internal IP address will help.
- Votes  `KEY`and  `TOKEN`in the `.env`? Run again`docker compose up -d` after making a change.
- [Common Issues](https://beszel.dev/guide/common-issues) in the Beszel Documentary.
</Step>

<Step title="Set Up Notifications">
For Beszel to warn you, it needs a channel. Open “Settings → Notifications.” Beszel offers two options:

- **Email**: Enter your email address. To do this, Beszel needs to be able to send emails. You can enter your email provider's SMTP settings in the admin settings, which you can access via the user menu.
- **Webhook / Push**: Beszel uses [Shoutrrr URLs](https://beszel.dev/guide/notifications/) and thus supports ntfy, Telegram, Discord, Gotify, and Matrix, among others. For example, to send a push notification to a cell phone via the public ntfy server, simply use:

```bash
ntfy://ntfy.sh/ein-langes-zufaelliges-topic
```

To do this, install the ntfy app and subscribe to the same topic. Anyone who knows the topic name can read the messages. So choose a long, random name—or set up your own ntfy server later. The exact URL format for each service is listed in the [Beszel documentation](https://beszel.dev/guide/notifications/). The [Notifications](/en/setup/notifications/) guide explains which channel is right for you and how to run ntfy yourself.
</Step>

<Step title="Set Alarms">
You set alerts on a per-system basis. In the system list, click the bell icon next to your server. A good place to start:

| Alarm | Proposal |
| --- | --- |
| Status | To: Notifies you if the server stops responding |
| Disk Usage | 85% or more |
| Memory Usage | 90% or higher, for 10 minutes or more |
| CPU Usage | 90% or higher, for 10 minutes or more |
| Temperature | only if your server reports sensor readings |

The duration helps prevent false alarms: A brief spike in load during an update is normal, but ten minutes of full load is not. If the hard drive alarm goes off, go to [“Hard Drive Full](/en/wiki/disk-full/)” to see where the space has gone. Using the “All Systems” tab, you can apply the same settings to any new server later on.
</Step>

<Step title="Connect Additional Servers">
Each additional server requires only one agent. Create a new system in the Hub using “Add System,” and launch the same agent stack on the server using the new key and token.  `HUB_URL`remains the same. Since the agent establishes the connection, this also works with a VPS in the cloud. For instructions on how to distribute tasks across multiple devices, see [“Multiple Devices: Assigning Roles](/en/wiki/multiple-devices/).”

You should always update Hub and Agent together when installing updates to ensure that their versions are compatible.
</Step>

</Steps>

<Callout title="Beszel complements, but does not replace, an external check">
If the entire server goes down, Beszel will also go down if it's running on that server. In that case, the status alert will only be helpful for other servers. [Uptime Kuma](/en/setup/uptime-kuma/) checks whether your services are accessible from the outside—ideally from a second location.
</Callout>
