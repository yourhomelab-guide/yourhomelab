Docker is the foundation for all further guides. Every service will run as a container, described in a `compose.yaml`. [What is Docker?](/en/wiki/what-is-docker/) explains what Docker is exactly.

## Why the official repository?

There are several ways to install Docker. Debian and Ubuntu ship their own package (`docker.io`), and Ubuntu also offers a snap package. Both are often older than the current version, and the Compose plugin is missing or lags behind. The snap package also has restrictions when accessing folders outside the home directory.

That's why you use **Docker's official apt repository** here. You get current versions through the regular package updates, including `docker compose`. The commands follow the official instructions for [Debian](https://docs.docker.com/engine/install/debian/) and [Ubuntu](https://docs.docker.com/engine/install/ubuntu/). If something doesn't work, check there whether anything has changed.

<Steps>

<Step title="Remove old or conflicting packages">
If a Docker version from the distribution is already installed, it conflicts with the official packages. This command finds and removes them. On a fresh server it finds nothing, and apt at most reports that there's nothing to do. That's fine.

```bash
sudo apt remove $(dpkg --get-selections docker.io docker-compose docker-doc docker-buildx podman-docker containerd runc 2>/dev/null | cut -f1)
```

Existing images and containers under `/var/lib/docker` are kept.
</Step>

<Step title="Get Docker's signing key">
apt uses this key to check that the packages really come from Docker and weren't changed on the way.

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL "https://download.docker.com/linux/$(. /etc/os-release && echo "$ID")/gpg" -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
```

The part `$(. /etc/os-release && echo "$ID")` fills in `debian` or `ubuntu` automatically.
</Step>

<Step title="Add the repository">
Now tell apt where the Docker packages are. The command detects by itself which Debian or Ubuntu version you're using.

```bash
sudo tee /etc/apt/sources.list.d/docker.sources > /dev/null <<EOF
Types: deb
URIs: https://download.docker.com/linux/$(. /etc/os-release && echo "$ID")
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt-get update
```

The output of `apt-get update` should now include a line with `download.docker.com`.

<Callout title="Debian and Ubuntu only">
The commands read the ID from `/etc/os-release`. On derived distributions like Linux Mint or Raspberry Pi OS, it doesn't always fit. In that case, use the matching instructions from the [official docs](https://docs.docker.com/engine/install/).
</Callout>
</Step>

<Step title="Install Docker and Compose">
These packages bring the Docker Engine (the service that runs containers), the `docker` command-line tool and the Compose plugin.

```bash
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

The Docker service starts right away and from now on at every boot. Check it:

```bash
systemctl status docker --no-pager
docker --version
docker compose version
```

The last two commands may still need `sudo` here if they report a permission error. You'll fix that in the next step.

Note `docker compose` with a space. That's the current plugin. You don't need the old standalone program `docker-compose` with a hyphen.
</Step>

<Step title="Add your user to the docker group">
Without this step you'd have to put `sudo` in front of every Docker command. Members of the `docker` group may control the Docker service directly.

```bash
sudo usermod -aG docker $USER
```

The new group only applies after a new login. Log out with `exit` and back in over SSH. After that, `groups` shows the `docker` group.

<Callout type="warning" title="The docker group is as powerful as root">
Anyone who can control Docker can start a container that mounts the server's complete file system, and so read and change everything. Only add users you'd also give sudo rights. You'll find background in the [official docs](https://docs.docker.com/engine/security/#docker-daemon-attack-surface).
</Callout>
</Step>

<Step title="Test with hello-world">
The `hello-world` image is a tiny test container. It prints a greeting and exits again.

```bash
docker run --rm hello-world
```

If you see `Hello from Docker!`, everything works: Docker downloaded the image, started a container, and you didn't need `sudo` for it. `--rm` deletes the stopped container right away.
</Step>

</Steps>

## Updates

Docker now comes from a regular apt repository and is updated with `sudo apt-get upgrade`, just like the rest of the system. If you've set up [automatic updates](/en/setup/automatic-updates/), note: by default, unattended-upgrades only installs updates from the distribution's sources, not from third-party repositories like Docker's. So plan a manual update every now and then:

```bash
sudo apt-get update && sudo apt-get upgrade
```
