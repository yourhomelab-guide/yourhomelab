A **stack** is a folder with a `compose.yaml`. It defines which containers should run, with which image, which ports and which data. Instead of typing long `docker run` commands, you describe the desired state in a file, and `docker compose` makes it happen. More in the article [Docker Compose](/en/wiki/docker-compose/).

As your first service, you use **whoami** from the Traefik developers. It's a tiny web server that only shows which request it receives. It stores nothing and needs no setup. That way you can focus entirely on Compose. You'll use the same container later to test the reverse proxy.

There's no reverse proxy yet at this point. So you reach the container directly at the server's IP address and a port.

<Steps>

<Step title="Create the stack folder">
Every service gets its own folder under `__ROOT__`. You run all `docker compose` commands in this folder.

```bash
mkdir -p __ROOT__/whoami
cd __ROOT__/whoami
```
</Step>

<Step title="Write compose.yaml">
Open a new file in the editor:

```bash
nano compose.yaml
```

Paste this content, save with `Ctrl+O` and `Enter`, and exit nano with `Ctrl+X`:

```yaml
services:
  whoami:
    image: traefik/whoami:latest
    container_name: whoami
    restart: unless-stopped
    ports:
      - "8080:80"
```

What the lines mean:

- `services:` lists the stack's containers. There's only one here, `whoami`.
- `image:` says which image Docker fetches from Docker Hub. For a test container, `latest` is fine. For real services, a fixed version is better; see [Images & tags](/en/wiki/images-tags/).
- `container_name:` gives the container a fixed, readable name.
- `restart: unless-stopped` automatically starts the container again after a crash or a server restart, unless you stopped it yourself. If a container keeps restarting, [Container in a restart loop](/en/wiki/restart-loop/) helps.
- `ports:` connects port `8080` on the server with port `80` in the container. The server is always on the left, the container on the right. If the port on the server is already taken, the container doesn't start; see [Port already in use](/en/wiki/port-in-use/).

Watch the indentation. YAML uses spaces, not tabs, and the indentation determines the structure.

If you later find a `compose.yaml` in a project's docs, the [Compose explainer](/en/tools/compose-explainer/) explains every line and flags typical problems.
</Step>

<Step title="Start the stack">
`up` creates and starts everything in the `compose.yaml`. `-d` (detached) runs the container in the background, so you get your terminal back.

```bash
docker compose up -d
```

The first time, Docker downloads the image. Then Compose reports that the `whoami` container has started.
</Step>

<Step title="Check the status">
`ps` shows the stack's containers, their state and the published ports.

```bash
docker compose ps
```

The `STATUS` column should say `Up`, and `PORTS` something like `0.0.0.0:8080->80/tcp`.
</Step>

<Step title="Test in the browser">
On your computer on the same network, open `http://__SERVER_IP__:8080`.

You'll see a short text page with `Hostname`, `IP` and your request's headers. That's the answer from the container.

It works directly on the server too:

```bash
curl http://localhost:8080
```

<Callout type="warning" title="Docker ports bypass UFW">
Ports from `ports:` are reachable even if you haven't allowed them in [UFW](/en/setup/firewall-ufw/). Docker adds its own firewall rules, which take effect before UFW's. At home behind the router, that's usually only visible on your home network. On a rented server, though, the port is immediately reachable **from the internet**. There, better write `"127.0.0.1:8080:80"`. Then the port only listens locally and you test with `curl`. Later the reverse proxy takes over anyway, and the services no longer need ports of their own.
</Callout>
</Step>

<Step title="Look at the logs">
Everything a container prints ends up in its logs. That's the first place to look when something doesn't work.

```bash
docker compose logs
docker compose logs -f
```

With `-f` (follow), new lines appear live. Reload the page in the browser and watch. Stop with `Ctrl+C`. The container keeps running.

[Troubleshooting: first steps](/en/wiki/first-steps/) shows how to get from an error message in the log to the cause.
</Step>

<Step title="Update">
This is how you bring a stack up to the image's latest state. `pull` downloads new images, and `up -d` only replaces the containers whose image has changed.

```bash
docker compose pull
docker compose up -d
```

You use the same `up -d` when you've changed the `compose.yaml`. Compose detects the change and recreates the container.
</Step>

<Step title="Stop and remove">
`down` stops the stack's containers and removes them, along with the network Compose created for the stack.

```bash
docker compose down
```

Your files in the stack folder stay untouched, including everything under `data/`. Another `docker compose up -d` restores the stack. Keep the `whoami` folder; you'll need it in the next guide.
</Step>

</Steps>

## The commands at a glance

| Command | Effect |
| --- | --- |
| `docker compose up -d` | Create the stack or bring it to the state of the `compose.yaml` |
| `docker compose ps` | Show the stack's containers and their state |
| `docker compose logs -f` | Follow the logs live |
| `docker compose pull` | Download new images |
| `docker compose down` | Stop and remove containers; data stays |

All commands refer to the `compose.yaml` in the current folder. If you get `no configuration file provided`, you're in the wrong folder.
