A **stack** is a folder with a file`compose.yaml`. It specifies which containers should run, with which image, which ports, and which data. Instead of typing long `docker run`commands, you describe the desired state in a file, and [Docker Compose](/en/wiki/docker-compose/) `docker compose`sets it up. Read more about this in the article "[Docker Compose](/en/wiki/docker-compose/)."

For your first service, use **`whoami`** from the Traefik developers. It’s a tiny web server that simply displays the requests it receives. It doesn’t store anything and requires no configuration. This allows you to focus entirely on Compose. You’ll also use the same container later to test the reverse proxy.

There is no reverse proxy set up here yet. Therefore, you can access the container directly using the server's IP address and a port.

<Steps>

<Step title="Create a Stack Folder">
Each service gets its own folder under `__ROOT__`. Run all `docker compose`commands in this folder.

```bash
mkdir -p __ROOT__/whoami
cd __ROOT__/whoami
```
</Step>

<Step title="Write a compose.yaml file">
Open a new file in the editor:

```bash
nano compose.yaml
```

Paste this content, save with  `Strg+O`and  , and`Enter` exit nano with `Strg+X`:

```yaml
services:
  whoami:
    image: traefik/whoami:latest
    container_name: whoami
    restart: unless-stopped
    ports:
      - "8080:80"
```

What these lines mean:

- `services:` lists the containers in the stack. There is only one here: `whoami`.
- `image:` specifies which image Docker retrieves from Docker Hub. This is fine`latest` for a test container. For production services, you should use a specific version; see [Images & Tags](/en/wiki/images-tags/).
- `container_name:` Gives the container a fixed, easy-to-read name.
- `restart: unless-stopped` Automatically restarts the container after a server crash or reboot, unless you've stopped it yourself. If a container keeps restarting, "[Container in a Restart Loop](/en/wiki/restart-loop/)" can help.
- `ports:` Connects the server's`8080` port to the container's`80` port. The server is always listed on the left, and the container on the right. If the port on the server is already in use, the container will not start; see "[Port in Use](/en/wiki/port-in-use/)."

Pay attention to the indentation. YAML uses spaces, not tabs, and the indentation determines the structure.

If you come across one later in`compose.yaml` a project's documentation, the [Compose Explainer](/en/werkzeuge/compose-erklaerer/) will explain each line to you and highlight common issues.
</Step>

<Step title="Start Stack">
`up` Creates and starts everything listed`compose.yaml` in the  file.  `-d`(detached) runs the container in the background, so you get your terminal back.

```bash
docker compose up -d
```

The first time, Docker downloads the image. After that, Compose reports that the container has started`whoami`.
</Step>

<Step title="Check Status">
`ps` Displays the containers in this stack, their status, and the published ports.

```bash
docker compose ps
```

The column should`STATUS` say`Up` [...], with `PORTS`[...]`0.0.0.0:8080->80/tcp`.
</Step>

<Step title="Test in the browser">
Open it on your computer on the same network`http://192.168.1.10:8080`. Replace  `192.168.1.10`with your server's IP address.

You'll see a short text page with `Hostname`,  and`IP` the headers from your request. This is the response from the container.

You can also do it directly on the server:

```bash
curl http://localhost:8080
```

<Callout type="warning" title="Bypassing UFW for Docker Ports">
Ports starting with  `ports:`are accessible even if you haven't opened them in [UFW](/en/setup/firewall-ufw/). Docker applies its own firewall rules, which take precedence over UFW's. At home behind a router, this is usually only visible on your home network. On a rented server, however, the port is immediately accessible **from the Internet**. In that case, it’s better to use `"127.0.0.1:8080:80"`. Then the port listens only locally, and you can test it with `curl`. Later on, the reverse proxy will take over anyway, and the services won’t need their own ports anymore.
</Callout>
</Step>

<Step title="View logs">
Everything a container outputs ends up in its logs. That's the first place to check if something isn't working.

```bash
docker compose logs
docker compose logs -f
```

Click (`-f`follow) to see new lines appear in real time. Refresh the page in your browser and watch what happens. Click to stop`Strg+C`. The container will continue to run.

["Troubleshooting: First Steps"](/en/wiki/first-steps/) explains how to identify the cause of an error based on an error message in the log.
</Step>

<Step title="Refresh">
Here's how to update a stack to the latest version of the image. It loads`pull` new images and `up -d`replaces only those containers whose images have changed.

```bash
docker compose pull
docker compose up -d
```

You use`up -d` the same one after you've changed`compose.yaml` it. Compose detects the change and recreates the container.
</Step>

<Step title="Stop and Remove">
`down` Stops the stack's containers and removes them along with the network that Compose created for the stack.

```bash
docker compose down
```

Your files in the Stack folder will remain untouched—including everything inside it`data/`. Running the command again `docker compose up -d`will restore the Stack. Leave the folder `whoami`as is; you'll need it in the next guide.
</Step>

</Steps>

## An Overview of the Commands

| Command | Effect |
| --- | --- |
| `docker compose up -d` | Create a stack or update`compose.yaml` it to the current version |
| `docker compose ps` | Display the stack's containers and their status |
| `docker compose logs -f` | Track Logs Live |
| `docker compose pull` | Download New Images |
| `docker compose down` | Stop and remove containers; data remains |

All commands refer to the file in`compose.yaml` the current folder. If you see `no configuration file provided`, you're in the wrong folder.
