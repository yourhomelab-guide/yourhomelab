Many services have their own user management systems. With five services, you have five passwords, five login pages, and five places where you have to create or lock a user account. [Single sign-on](/en/wiki/single-sign-on/) solves this problem: A central service verifies your identity, and the other services trust it.

Pocket ID is one such central service—a so-called **OIDC provider**. OIDC (OpenID Connect) is the open standard through which a service says, “Please log in there and come back with a confirmation.” Pocket ID supports only one type of login: **passkeys**. A passkey is a key pair managed by your device (cell phone, laptop, password manager, or hardware key). There is no password that anyone can guess or intercept.

<Callout title="Requirement: HTTPS">
Browsers only allow passkeys on sites with valid HTTPS. Therefore, set up your reverse proxy first, for example, using [Traefik](/en/setup/reverse-proxy-traefik/) or [Nginx Proxy Manager](/en/setup/reverse-proxy-npm/). Pocket ID will then run under `id.__DOMAIN__`.
</Callout>

<Steps>

<Step title="Write the `compose.yaml` and `.env` files">
Like any other service, Pocket ID gets its own folder under `__ROOT__`. The database (SQLite) and uploaded images are stored in `data/`, so they're included in your backup.

<ServiceFiles id="pocket-id" />

Two variables are important:

- `APP_URL` is Pocket ID's public address. It must be exactly correct, because passkeys are permanently tied to this domain. If the domain changes later, the registered passkeys will no longer work.
- `TRUST_PROXY=true` Pocket ID says that it runs behind a reverse proxy. Then, in the audit log, it sees your visitors' actual IP addresses instead of the proxy's.
</Step>

<Step title="Start and Check">
Start the stack and check the log. If there are no errors and the container is running, Pocket ID is ready.

```bash
cd __ROOT__/pocket-id
docker compose up -d
docker compose logs -f pocket-id
```

Press  to exit`Strg+C` the log view; the container will continue to run.
</Step>

<Step title="Create an Admin Account">
Immediately after the first launch, there are no users yet. You create the first one on the setup page. That user automatically becomes an administrator.

Open in your browser:

```text
https://id.__DOMAIN__/setup
```

Enter your first name, last name, username, and email address, then submit the form.

<Callout type="warning" title="Don't wait">
The setup page is publicly accessible as long as no account has been created yet. Therefore, create the admin account immediately after starting the system.
</Callout>
</Step>

<Step title="Register Passkey">
After you create an account, Pocket ID will prompt you to set up a passkey. Your browser or operating system will then ask where you want to store the passkey: in a password manager, on your phone, or on a hardware key such as a YubiKey.

Next, go to "**My Account" and** register a **second passkey** on a different device. That way, if you lose your phone, you'll still be able to log in.

Try logging out and then logging back in to make sure everything is working properly.
</Step>

<Step title="Emergency: Locked Out">
If you no longer have access to one of your passkeys, you can generate a one-time login link on the server. It's valid for one hour.

```bash
cd __ROOT__/pocket-id
docker compose exec pocket-id /app/pocket-id one-time-access-token DEIN_BENUTZERNAME
```

The output contains a URL. Open it, log in using it, and register a new passkey right away.
</Step>

<Step title="Create an OIDC Client for a Service">
To allow a service to log in via Pocket ID, you need to create an **OIDC client** for it. This is an entry that specifies which service is allowed to request logins and where Pocket ID redirects users afterward.

1. In the admin area, open "**OIDC Clients"** and click "**Add OIDC Client**."
2. Enter a **name**, such as the name of the service. It will appear on the login page.
3. Enter the **callback URL**. This is the address within the service to which Pocket ID redirects you after you log in. You can find this information in the documentation for the respective service. For [Tinyauth](/en/setup/tinyauth/), for example, it is `https://login.__DOMAIN__/api/oauth/callback/generic`.
4. Save the client.

Pocket ID will then display **the client ID**, **client secret**, and **OIDC Discovery URL**:

```text
https://id.__DOMAIN__/.well-known/openid-configuration
```

Enter these three values in the service. Many services only need the Discovery URL (sometimes called the "Issuer URL," in which case it omits the portion starting with `/.well-known`) and retrieve the rest on their own. The secret belongs in the  `.env`of the service, not in the `compose.yaml`. If you lose it, you can generate a new one in Pocket ID.

The Pocket ID documentation includes ready-made guides for many popular services: [pocket-id.org/docs](https://pocket-id.org/docs).
</Step>

<Step title="Invite more users (optional)">
Under **"Users**," you can create additional accounts, such as for your family. To allow someone to register their first passkey, generate a one-time **login code** or sign-in link for the account and share it with them.

**User** **groups** let you control who is allowed to use which service: In the OIDC client, you can then select the appropriate group under "**Allowed User Groups**."
</Step>

</Steps>

## What about services without OIDC?

Pocket ID only protects services that support OIDC natively. Many small tools have no login process at all or only a simple one. For these, there’s [Tinyauth](/en/setup/tinyauth/): It acts as middleware in the reverse proxy in front of the service and retrieves the login credentials before the request even arrives. Tinyauth can use Pocket ID as an authentication method. This way, you can log in everywhere with the same passkey.
