Nicht jeder Dienst hat einen eigenen Login. Das Traefik-Dashboard, ein Datei-Browser oder ein kleines Statistik-Tool sind ohne Schutz für jeden im Internet offen, sobald sie eine öffentliche Subdomain haben. Andere Dienste haben zwar einen Login, aber keinen, dem du vertrauen möchtest.

Tinyauth löst das mit **Forward Auth**. Dabei fragt der Reverse Proxy vor jeder Anfrage bei Tinyauth nach: "Ist dieser Besucher angemeldet?" Wenn ja, geht die Anfrage an den Dienst. Wenn nein, leitet der Proxy auf die Login-Seite von Tinyauth um. Der Dienst selbst merkt davon nichts. In Traefik ist Forward Auth eine **Middleware**, also ein Zwischenschritt, den du per Label an beliebige Dienste hängst.

<Steps>

<Step title="Benutzer anlegen">
Ein Tinyauth-Benutzer besteht aus Benutzername und einem **bcrypt-Hash** des Passworts. Ein Hash ist eine Einweg-Umrechnung: Tinyauth kann damit prüfen, ob ein Passwort stimmt, aber niemand kann das Passwort daraus zurückrechnen.

Am einfachsten erzeugt Tinyauth den Benutzer selbst:

```bash
docker run -it --rm ghcr.io/tinyauthapp/tinyauth:v5 user create --interactive
```

Der Befehl fragt nach Benutzername und Passwort und gibt eine Zeile wie `admin:$2a$10$...` aus. Diese ganze Zeile ist dein Benutzer. Beantworte die Frage nach dem Docker-Format mit **Nein**, denn im nächsten Schritt schützen einfache Anführungszeichen den Hash. Mehrere Benutzer trennst du mit Komma.

Ohne Docker geht es mit dem Werkzeug [Passwort-Hash](/de/werkzeuge/passwort-hash/). Es rechnet den Hash direkt in deinem Browser aus und gibt dir die fertige Zeile für die `.env`.
</Step>

<Step title="compose.yaml und .env schreiben">
Tinyauth läuft unter `login.__DOMAIN__`. Es setzt sein Login-Cookie für die ganze Domain `__DOMAIN__`. Deshalb müssen alle Dienste, die du schützen willst, Subdomains derselben Domain sein.

<ServiceFiles id="tinyauth" />

Trag in der `.env` den Benutzer aus Schritt 1 ein, in **einfachen Anführungszeichen**. Sonst hält Docker Compose die `$`-Zeichen im Hash für Variablen und zerstört ihn:

```bash
TINYAUTH_USERS='admin:$2a$10$...'
```

Mit Traefik enthält die `compose.yaml` schon die Definition der Middleware `tinyauth`. Sie sagt Traefik, wo es vor jeder Anfrage nachfragen soll:

```yaml
      - traefik.http.middlewares.tinyauth.forwardauth.address=http://tinyauth:3000/api/auth/traefik
```

Traefik erreicht Tinyauth über das gemeinsame Netzwerk `__NETWORK__` direkt unter dem Containernamen, deshalb steht hier `http://` und kein öffentlicher Hostname.

Zwei weitere Einstellungen sind schon gesetzt: `TINYAUTH_AUTH_SECURECOOKIE=true` schickt das Login-Cookie nur über HTTPS, und `TINYAUTH_AUTH_TRUSTEDPROXIES` lässt Tinyauth die echte IP deiner Besucher sehen. Ein Secret brauchst du seit Version 4 nicht mehr, Tinyauth speichert seine Sitzungen in einer kleinen Datenbank unter `data/`.
</Step>

<Step title="Starten und Login testen">

```bash
cd __ROOT__/tinyauth
docker compose up -d
docker compose logs -f tinyauth
```

Öffne `https://login.__DOMAIN__` und melde dich mit deinem Benutzer an. Klappt das, läuft Tinyauth. Geschützt ist aber noch nichts. Lehnt Tinyauth dein Passwort ab, ist meist der Hash in der `.env` beschädigt: Prüfe die einfachen Anführungszeichen. Startet der Container immer wieder neu, hilft [Container in der Neustart-Schleife](/de/nachschlagen/container-neustart-schleife/).
</Step>

<Step title="Einen Dienst schützen">
Jetzt hängst du die Middleware an den Router eines Dienstes. Router heißen auf dieser Seite wie der Dienst, also z. B. `traefik.http.routers.uptime-kuma` für Uptime Kuma. Ergänze in dessen `compose.yaml` ein Label:

```yaml
      - traefik.http.routers.uptime-kuma.middlewares=tinyauth
```

Ein gutes erstes Ziel ist das Traefik-Dashboard. Sein Router heißt `dashboard`. In `__ROOT__/traefik/compose.yaml` steht schon eine Middleware, die nur das Heimnetz durchlässt. Ersetze diese beiden Zeilen:

```yaml
      - traefik.http.middlewares.dashboard-lan.ipallowlist.sourcerange=10.0.0.0/8,192.168.0.0/16
      - traefik.http.routers.dashboard.middlewares=dashboard-lan
```

durch:

```yaml
      - traefik.http.routers.dashboard.middlewares=tinyauth
```

Ein Router hat nur eine `middlewares`-Zeile. Willst du mehrere Middlewares, trennst du sie dort mit Komma, z. B. `dashboard-lan,tinyauth` für „nur Heimnetz **und** Login“. Dasselbe gilt für Dienste wie Dockhand und Homepage, die die Vorlagen von Haus aus aufs Heimnetz beschränken.

Danach den jeweiligen Stack neu starten, damit Traefik die Labels liest:

```bash
cd __ROOT__/traefik
docker compose up -d
```

Öffne das Dashboard in einem privaten Browserfenster. Du solltest zuerst auf `login.__DOMAIN__` landen und nach dem Login zurückgeleitet werden.

<Callout type="warning" title="Nicht vor alles schalten">
Apps auf dem Handy (z. B. Nextcloud, Immich, Vaultwarden) sprechen direkt mit der API des Dienstes und können keine Login-Seite anzeigen. Schalte Tinyauth nur vor Dienste, die du im Browser nutzt, oder vor solche ohne eigenen Login.
</Callout>
</Step>

<Step title="Pocket ID als Anmeldeweg (optional)">
Statt mit Passwort kannst du dich bei Tinyauth auch per Passkey über [Pocket ID](/de/einrichten/pocket-id/) anmelden.

Lege in Pocket ID einen OIDC-Client an, z. B. mit dem Namen `Tinyauth`, und dieser Callback-URL:

```text
https://login.__DOMAIN__/api/oauth/callback/pocketid
```

Trag Client-ID und Secret in die `.env` von Tinyauth ein:

```bash
POCKET_ID_CLIENT_ID=DEINE_CLIENT_ID
POCKET_ID_CLIENT_SECRET=DEIN_CLIENT_SECRET
```

Und ergänze in der `compose.yaml` unter `environment`:

```yaml
      - TINYAUTH_OAUTH_PROVIDERS_POCKETID_CLIENTID=${POCKET_ID_CLIENT_ID}
      - TINYAUTH_OAUTH_PROVIDERS_POCKETID_CLIENTSECRET=${POCKET_ID_CLIENT_SECRET}
      - TINYAUTH_OAUTH_PROVIDERS_POCKETID_AUTHURL=https://id.__DOMAIN__/authorize
      - TINYAUTH_OAUTH_PROVIDERS_POCKETID_TOKENURL=https://id.__DOMAIN__/api/oidc/token
      - TINYAUTH_OAUTH_PROVIDERS_POCKETID_USERINFOURL=https://id.__DOMAIN__/api/oidc/userinfo
      - TINYAUTH_OAUTH_PROVIDERS_POCKETID_REDIRECTURL=https://login.__DOMAIN__/api/oauth/callback/pocketid
      - TINYAUTH_OAUTH_PROVIDERS_POCKETID_SCOPES=openid email profile groups
      - TINYAUTH_OAUTH_PROVIDERS_POCKETID_NAME=Pocket ID
      - TINYAUTH_OAUTH_WHITELIST=DEINE_EMAIL_IN_POCKET_ID
```

`TINYAUTH_OAUTH_WHITELIST` ist wichtig: Trag dort die E-Mail-Adresse deines Pocket-ID-Kontos ein. Ohne diese Zeile darf sich jeder anmelden, der ein Konto in Pocket ID hat. Mehrere E-Mail-Adressen trennst du mit Komma. Soll Tinyauth direkt zu Pocket ID weiterleiten, ohne eigene Login-Seite, ergänzt du `TINYAUTH_OAUTH_AUTOREDIRECT=pocketid`.

Nach `docker compose up -d` zeigt die Login-Seite einen zusätzlichen Button „Pocket ID“. Details stehen im [Pocket-ID-Guide von Tinyauth](https://tinyauth.app/docs/guides/pocket-id).
</Step>

</Steps>

## Mit Nginx Proxy Manager

Tinyauth funktioniert auch mit Nginx Proxy Manager, nur ohne Labels. Dort trägst du für jeden geschützten Proxy-Host im Tab **Advanced** einen Konfigurationsblock ein, der jede Anfrage über `auth_request` an Tinyauth weiterreicht. Beim Proxy-Host von Tinyauth selbst muss **Block Common Exploits** ausgeschaltet sein, sonst blockiert NPM die Weiterleitung zurück zum Dienst. Die vollständige Konfiguration steht in der [Tinyauth-Doku zu Nginx Proxy Manager](https://tinyauth.app/docs/guides/nginx-proxy-manager).
