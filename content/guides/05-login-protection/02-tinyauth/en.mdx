Not every service has a login of its own. The Traefik dashboard, a file browser or a small statistics tool are open to anyone on the internet as soon as they have a public subdomain. Other services do have a login, but not one you'd want to trust.

Tinyauth solves this with **forward auth**. Before every request, the reverse proxy asks Tinyauth: "Is this visitor logged in?" If yes, the request goes to the service. If not, the proxy redirects to Tinyauth's login page. The service itself notices nothing. In Traefik, forward auth is a **middleware**, an intermediate step you attach to any service with a label.

<Steps>

<Step title="Create a user">
A Tinyauth user consists of a user name and a **bcrypt hash** of the password. A hash is a one-way conversion: Tinyauth can use it to check whether a password is right, but nobody can calculate the password back from it.

The easiest way is to let Tinyauth create the user itself:

```bash
docker run -it --rm ghcr.io/tinyauthapp/tinyauth:v5 user create --interactive
```

The command asks for a user name and password and prints a line like `admin:$2a$10$...`. That whole line is your user. Answer **No** to the question about the Docker format, because in the next step single quotes protect the hash. Separate several users with commas.

Without Docker, use the [password hash](/en/tools/password-hash/) tool. It calculates the hash right in your browser and gives you the finished line for the `.env`.
</Step>

<Step title="Write compose.yaml and .env">
Tinyauth runs at `login.__DOMAIN__`. It sets its login cookie for the whole domain `__DOMAIN__`. That's why all services you want to protect must be subdomains of the same domain.

<ServiceFiles id="tinyauth" />

Put the user from step 1 into the `.env`, in **single quotes**. Otherwise Docker Compose treats the `$` signs in the hash as variables and destroys it:

```bash
TINYAUTH_USERS='admin:$2a$10$...'
```

With Traefik, the `compose.yaml` already contains the definition of the `tinyauth` middleware. It tells Traefik where to ask before each request:

```yaml
      - traefik.http.middlewares.tinyauth.forwardauth.address=http://tinyauth:3000/api/auth/traefik
```

Traefik reaches Tinyauth directly by its container name through the shared `__NETWORK__` network, which is why this says `http://` and not a public host name.

Two more settings are already in place: `TINYAUTH_AUTH_SECURECOOKIE=true` only sends the login cookie over HTTPS, and `TINYAUTH_AUTH_TRUSTEDPROXIES` lets Tinyauth see your visitors' real IP. Since version 4 you no longer need a secret; Tinyauth stores its sessions in a small database under `data/`.
</Step>

<Step title="Start and test the login">

```bash
cd __ROOT__/tinyauth
docker compose up -d
docker compose logs -f tinyauth
```

Open `https://login.__DOMAIN__` and log in with your user. If that works, Tinyauth is running. But nothing is protected yet. If Tinyauth rejects your password, the hash in the `.env` is usually damaged: check the single quotes. If the container keeps restarting, [Container in a restart loop](/en/wiki/restart-loop/) helps.
</Step>

<Step title="Protect a service">
Now attach the middleware to a service's router. On this site, routers are named like the service, e.g. `traefik.http.routers.uptime-kuma` for Uptime Kuma. Add a label to its `compose.yaml`:

```yaml
      - traefik.http.routers.uptime-kuma.middlewares=tinyauth
```

A good first target is the Traefik dashboard. Its router is called `dashboard`. `__ROOT__/traefik/compose.yaml` already contains a middleware that only lets the home network through. Replace these two lines:

```yaml
      - traefik.http.middlewares.dashboard-lan.ipallowlist.sourcerange=10.0.0.0/8,192.168.0.0/16
      - traefik.http.routers.dashboard.middlewares=dashboard-lan
```

with:

```yaml
      - traefik.http.routers.dashboard.middlewares=tinyauth
```

A router has only one `middlewares` line. If you want several middlewares, separate them there with commas, e.g. `dashboard-lan,tinyauth` for "home network only **and** login". The same goes for services like Dockhand and Homepage, which the templates restrict to the home network by default.

Then restart the stack so Traefik reads the labels:

```bash
cd __ROOT__/traefik
docker compose up -d
```

Open the dashboard in a private browser window. You should land on `login.__DOMAIN__` first and be sent back after logging in.

<Callout type="warning" title="Don't put it in front of everything">
Phone apps (e.g. Nextcloud, Immich, Vaultwarden) talk directly to the service's API and can't show a login page. Only put Tinyauth in front of services you use in the browser, or in front of those without a login of their own.
</Callout>
</Step>

<Step title="Pocket ID as a sign-in method (optional)">
Instead of a password, you can also sign in to Tinyauth with a passkey through [Pocket ID](/en/setup/pocket-id/).

In Pocket ID, create an OIDC client, e.g. named `Tinyauth`, with this callback URL:

```text
https://login.__DOMAIN__/api/oauth/callback/pocketid
```

Put the client ID and secret into Tinyauth's `.env`:

```bash
POCKET_ID_CLIENT_ID=DEINE_CLIENT_ID
POCKET_ID_CLIENT_SECRET=DEIN_CLIENT_SECRET
```

And add this under `environment` in the `compose.yaml`:

```yaml
      - TINYAUTH_OAUTH_PROVIDERS_POCKETID_CLIENTID=${POCKET_ID_CLIENT_ID}
      - TINYAUTH_OAUTH_PROVIDERS_POCKETID_CLIENTSECRET=${POCKET_ID_CLIENT_SECRET}
      - TINYAUTH_OAUTH_PROVIDERS_POCKETID_AUTHURL=https://id.__DOMAIN__/authorize
      - TINYAUTH_OAUTH_PROVIDERS_POCKETID_TOKENURL=https://id.__DOMAIN__/api/oidc/token
      - TINYAUTH_OAUTH_PROVIDERS_POCKETID_USERINFOURL=https://id.__DOMAIN__/api/oidc/userinfo
      - TINYAUTH_OAUTH_PROVIDERS_POCKETID_REDIRECTURL=https://login.__DOMAIN__/api/oauth/callback/pocketid
      - TINYAUTH_OAUTH_PROVIDERS_POCKETID_SCOPES=openid email profile groups
      - TINYAUTH_OAUTH_PROVIDERS_POCKETID_NAME=Pocket ID
      - TINYAUTH_OAUTH_WHITELIST=DEINE_EMAIL_IN_POCKET_ID
```

Replace the uppercase placeholders with your values. `TINYAUTH_OAUTH_WHITELIST` is important: enter the email address of your Pocket ID account there. Without this line, anyone with an account in Pocket ID may sign in. Separate several email addresses with commas. If Tinyauth should redirect straight to Pocket ID without its own login page, add `TINYAUTH_OAUTH_AUTOREDIRECT=pocketid`.

After `docker compose up -d`, the login page shows an additional "Pocket ID" button. Details are in [Tinyauth's Pocket ID guide](https://tinyauth.app/docs/guides/pocket-id).
</Step>

</Steps>

## With Nginx Proxy Manager

Tinyauth also works with Nginx Proxy Manager, just without labels. There, for every protected proxy host, you add a configuration block in the **Advanced** tab that passes each request to Tinyauth with `auth_request`. On Tinyauth's own proxy host, **Block Common Exploits** must be turned off, otherwise NPM blocks the redirect back to the service. The complete configuration is in the [Tinyauth docs for Nginx Proxy Manager](https://tinyauth.app/docs/guides/nginx-proxy-manager).
