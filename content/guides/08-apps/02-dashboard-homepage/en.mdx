title: "Dashboard with Homepage"
description: "Homepage is the start page for your homelab: all services sit as tiles on one page, with status, live values from Uptime Kuma or AdGuard Home and a search bar. The configuration lives in a few YAML files."
level: 1
minutes: 25
requires: [Docker Compose, Reverse proxy]
services: [homepage]
---

With every service, the list of addresses you have to remember grows. [Homepage](https://gethomepage.dev) collects them on one page. Every service gets a tile with an icon, a link and, if you like, live data: how many requests AdGuard Home has blocked, whether everything is green in Uptime Kuma, whether a container is running. The page works well as the browser start page, for the family too.

Homepage has no click interface for setup. You describe everything in YAML files, just like in a `compose.yaml`. That sounds like more work, but has an advantage: the files live in `__ROOT__`, end up in the backup and can be versioned with Git.

<OneWay />

If you'd rather build with drag and drop in the browser, take a look at [Homarr](https://homarr.dev). Homarr has a graphical editor, user accounts and many integrations, but is somewhat heavier. Both paths lead to a good dashboard.

<Callout type="warning" title="Dashboards show a lot">
A dashboard with widgets reveals which services you run and shows data from them. The credentials for the widgets live in the configuration. So don't expose Homepage to the internet unprotected. Put a login in front (last step) or only reach it from your home network and through a [VPN](/en/setup/vpn-wireguard/).
</Callout>

<Steps>

<Step title="Start Homepage">
Create the folder and, in it, `compose.yaml` and `.env`:

```bash
mkdir -p __ROOT__/homepage
cd __ROOT__/homepage
```

<ServiceFiles id="homepage" />

The stack consists of two containers. `homepage` is the dashboard. `socket-proxy` gives it read access to Docker; more on that in the step "Connect Docker".

The `HOMEPAGE_ALLOWED_HOSTS` variable in the `.env` is important. For security reasons, Homepage only answers requests to addresses listed there. It must contain exactly the address you type in the browser, without `https://`. Separate several entries with commas, without spaces. If you don't use a reverse proxy, the server's IP with port goes in, so `__SERVER_IP__:3002`.

```bash
docker compose up -d
docker compose logs -f homepage
```

On the first start, Homepage creates example files in `__DATA(homepage)__/config`. Open `https://home.__DOMAIN__`. You'll see a page with placeholder tiles. If you see an error message about the host check instead, compare the address in the log with `HOMEPAGE_ALLOWED_HOSTS`.
</Step>

<Step title="The configuration files">
Everything you set up lives in `__DATA(homepage)__/config`. The most important files:

| File | Content |
| --- | --- |
| `settings.yaml` | Title, language, colors, layout |
| `services.yaml` | Your services as tiles, in groups |
| `widgets.yaml` | The bar at the top: search, time, weather |
| `bookmarks.yaml` | Simple link lists without status |
| `docker.yaml` | Connection to Docker |

The files belong to your user (through `PUID` and `PGID` in the `.env`), so you edit them without `sudo`. Homepage reads them again on every page reload; there's no need to restart the container. Watch the indentation: YAML works with spaces, never with tabs. Homepage shows a broken entry as an error on the page.

Start with `settings.yaml` (set `language` to `en` for an English interface):

```yaml
title: Homelab
language: de
```
</Step>

<Step title="Add services">
In `services.yaml`, you create groups and, inside them, the services. Replace the example content with something like this:

```yaml
- Werkzeuge:
    - Vaultwarden:
        icon: vaultwarden.png
        href: https://vault.__DOMAIN__
        description: Passwörter
        siteMonitor: http://vaultwarden:80

- Betrieb:
    - Uptime Kuma:
        icon: uptime-kuma.png
        href: https://status.__DOMAIN__
        description: Erreichbarkeit
    - Beszel:
        icon: beszel.png
        href: https://beszel.__DOMAIN__
        description: Serverwerte
```

Group names and descriptions are free text, so name them whatever you like. The fields in detail:

- `href` is the link the tile opens.
- `icon` fetches an icon from the [Dashboard Icons](https://github.com/homarr-labs/dashboard-icons). With `sh-` in front, you use the icons from [selfh.st/icons](https://selfh.st/icons/); with `mdi-`, general icons.
- `siteMonitor` checks an address and shows a dot with the response time. Use the **internal** address made of container name and port here. Homepage sits in the proxy network `__NETWORK__` and reaches the other containers directly. That also works when the service is behind a login.

All options are in the [docs on services.yaml](https://gethomepage.dev/configs/services/).
</Step>

<Step title="Add widgets">
There are two kinds of widgets.

**Info widgets** sit at the top of the page and go into `widgets.yaml`:

```yaml
- search:
    provider: duckduckgo
    target: _blank
- datetime:
    text_size: xl
    format:
      dateStyle: long
      timeStyle: short
```

**Service widgets** are attached to a tile and show data from the service. Homepage queries the service's API for this. Two examples for `services.yaml`:

```yaml
- Betrieb:
    - Uptime Kuma:
        icon: uptime-kuma.png
        href: https://status.__DOMAIN__
        widget:
          type: uptimekuma
          url: http://uptime-kuma:3001
          slug: homelab
    - AdGuard Home:
        icon: adguard-home.png
        href: https://adguard.__DOMAIN__
        widget:
          type: adguard
          url: http://adguard-home:3000
          username: admin
          password: "{{HOMEPAGE_VAR_ADGUARD_PASSWORD}}"
```

The Uptime Kuma widget reads a [status page](/en/setup/uptime-kuma/); `slug` is its short name. The AdGuard widget needs the web interface's credentials.

Don't write passwords directly into the YAML file. Homepage replaces `{{HOMEPAGE_VAR_…}}` with the environment variable of the same name. Add this under `environment` for the `homepage` service in the `compose.yaml`:

```yaml
      - HOMEPAGE_VAR_ADGUARD_PASSWORD=${HOMEPAGE_VAR_ADGUARD_PASSWORD}
```

Put the value into the `.env` and restart with `docker compose up -d`. That way secrets stay in one place; see [.env & secrets](/en/setup/env-secrets/). The list of all widgets is in the [Homepage docs](https://gethomepage.dev/widgets/).
</Step>

<Step title="Connect Docker">
For every tile, Homepage can show whether the container is running and how much CPU and RAM it uses. For that, it has to be able to ask Docker.

The obvious way would be to mount the Docker socket `/var/run/docker.sock` into the container. Docker is controlled through this file. **Whoever has access to the socket has root rights on the server**: they can start containers that mount the whole file system. The `:ro` (read-only) suffix doesn't change that. It only protects the file itself, not the commands sent through it.

That's why the stack contains the `socket-proxy`. It has the socket but only lets read requests through (`POST=0`), and only for containers (`CONTAINERS=1`). Homepage talks to the proxy instead of Docker. The proxy is only reachable within the stack, not from outside.

Add the proxy to `docker.yaml`:

```yaml
my-docker:
  host: socket-proxy
  port: 2375
```

Now you can connect a tile with a container. Add this to the service in `services.yaml`:

```yaml
        server: my-docker
        container: vaultwarden
```

Alternatively, describe the tile right at the service. Homepage finds containers with matching **labels** automatically. In Vaultwarden's `compose.yaml`, that would look like this:

```yaml
    labels:
      - homepage.group=Werkzeuge
      - homepage.name=Vaultwarden
      - homepage.icon=vaultwarden.png
      - homepage.href=https://vault.__DOMAIN__
      - homepage.description=Passwörter
```

If you use Traefik, the service already has a `labels` block. The Homepage labels simply go in alongside. You can mix both ways. To start with, `services.yaml` is clearer, because everything is in one place.
</Step>

<Step title="Secure access">
Finally, make sure not everyone can see your dashboard. Three ways, from the simplest to the most comfortable:

- **Home network only**: that's the default. With Traefik or Caddy, the template only lets addresses from the home network through; with Nginx Proxy Manager, you create an access list for this. On the go, you then reach Homepage through a [VPN](/en/setup/vpn-wireguard/).
- **Login in front**: with Traefik, put [Tinyauth](/en/setup/tinyauth/) or [Pocket ID](/en/setup/pocket-id/) in front of Homepage as middleware. One login then protects all services the same way.
- **Built-in password**: since version 2, Homepage has a simple login with a password or OIDC. The variables for it are in the [installation guide](https://gethomepage.dev/installation/#security-authentication).

You'll find more on this topic under [Keeping the attack surface small](/en/wiki/attack-surface/).
</Step>

</Steps>
