[Home Assistant](https://www.home-assistant.io) is the hub for your smart home. It communicates with thousands of devices and services—from heating thermostats to power outlets to weather stations—and connects them through automations. Most of this happens locally, without going through a manufacturer’s cloud.

Before you get started, you'll need to make a decision that doesn't come into play with other services: **how** to install Home Assistant.

## Home Assistant OS in a VM or container?

Home Assistant is available in two officially supported versions:

- **Home Assistant OS (HAOS)** is a complete, lightweight operating system designed exclusively for Home Assistant. It automatically handles updates and backups and includes an app store for **apps** (formerly called “add-ons”). This lets you install apps like Zigbee2MQTT, an MQTT broker, or a code editor with a single click. On a Homelab server, HAOS runs in a **virtual machine**, for example on [Proxmox VE](/en/wiki/proxmox-ve/).
- **Home Assistant Container** is simply the application as a Docker image. It fits perfectly with the approach this site takes: one instance`compose.yaml`, data stored locally`__ROOT__`, and updates via a new image. There are no apps for this. Anything you need—such as an MQTT broker—you run as a separate container alongside it.

| | HAOS in a VM | Container |
|---|---|---|
| Updates | with a single click in the interface, including the operating system | New image tag, as with every stack |
| Apps (Add-ons) | yes | No, additional services as separate containers |
| Backup | Built-in, fully recoverable | Built-in for Home Assistant; additional services sold separately |
| Resources | Your own VM, at least 2 GB of RAM, and 2 CPU cores | Runs in the background; usually requires a few hundred MB of RAM |
| Requirement | Hypervisors such as Proxmox | Docker, which you already have |
| Some features, such as Thread or Z-Wave | Fully set up via apps | set it up yourself |

**My honest recommendation:** If your server runs on Proxmox or you're just getting started, use **HAOS in a VM**. This is the option recommended by the Home Assistant project. Most guides and forum posts are based on this setup, and updates require very little effort on your part. If, on the other hand, your server is a simple Linux system with Docker—as described in the guides on this site—and you don’t want to run a VM for it, the **container** is a good choice. You’ll have to do without the apps, but you’ll gain a unified operating environment for all services.

For HAOS on Proxmox, download the KVM/Proxmox `qcow2`image from the [official guide](https://www.home-assistant.io/installation/alternative), import it as the hard drive for a new VM, and set the firmware to UEFI (OVMF). Home Assistant only starts with UEFI. From this guide, you’ll then only need the steps for the reverse proxy, the trusted proxies, and the USB drive. The proxy will then forward traffic to the VM’s IP address instead of []`host.docker.internal`, the UFW rules on the Docker server are no longer needed, and as the trusted proxy, enter the IP address of the server running your reverse proxy.

The following steps describe the **container**.

<Steps>

<Step title="Why Host Network?">
Normally, each container runs on its own Docker network, and only exposed ports are accessible. However, Home Assistant often finds devices on the home network on its own, for example via **mDNS** (devices register on the local network using their names) or **SSDP/UPnP**. This discovery process uses broadcast and multicast, which cannot leave a standard Docker network.

That's why Home Assistant runs with `network_mode: host`. The container then shares the network with the server itself. There is no port forwarding; Home Assistant listens directly on port  `8123`of the server.

This has two consequences:

- Home Assistant **cannot** be on your proxy network`__NETWORK__`. A container with a host network cannot be on any other network. The reverse proxy must therefore access Home Assistant via the server's address. The step on the reverse proxy shows you how to do this.
- For Home Assistant, your **firewall** applies just as it does for any other program running directly on the server. The port is`8123` closed until you open it.

For this reason, there is no ready-made template for Home Assistant under "Services": The templates automatically connect each service to the proxy network, which doesn't work with the host network. So`compose.yaml` you'll have to write the template yourself.
</Step>

<Step title="Create a directory and a compose.yaml file">
```bash
mkdir -p __ROOT__/home-assistant __DATA(home-assistant)__/config
cd __ROOT__/home-assistant
nano compose.yaml
```

```yaml
services:
  home-assistant:
    image: ghcr.io/home-assistant/home-assistant:2026.9
    container_name: home-assistant
    restart: unless-stopped
    # Required for device discovery (mDNS, SSDP) in your LAN
    network_mode: host
    # Give Home Assistant time to close its database on shutdown
    stop_grace_period: 60s
    environment:
      - TZ=__TZ__
    volumes:
      - __DATA(home-assistant)__/config:/config
      - /etc/localtime:/etc/localtime:ro
      # Only needed for Bluetooth devices
      - /run/dbus:/run/dbus:ro
```

A new version of Home Assistant is released every month. The tag only `2026.9`includes this month's bug fixes. To upgrade to the next version, you need to manually change the tag, read the notes on breaking changes in [the](https://www.home-assistant.io/blog/categories/release-notes/) [release blog](https://www.home-assistant.io/blog/categories/release-notes/) beforehand, and restart. [Renovate](/en/setup/updates-renovate/) can automatically create a pull request for you.

The official template also sets `privileged: true`. This gives the container almost full access to the server. You don't need this as long as you specifically grant access to individual devices, as shown in the step for the USB flash drive.
</Step>

<Step title="Open and Start the Firewall">
To set it up for the first time, open port  `8123`for your home network. Customize the network to match yours:

```bash
sudo ufw allow from 192.168.1.0/24 to any port 8123 proto tcp
```

Then you start the container:

```bash
docker compose up -d
docker compose logs -f home-assistant
```

In your browser`http://__SERVER_IP__:8123`, go to [your server's IP address]. A wizard will set up your account and ask for your location, time zone, and units. After that, Home Assistant will display the devices it has found on the network.
</Step>

<Step title="Set Up a Reverse Proxy">
For HTTPS and a clean URL, place Home Assistant behind your reverse proxy. Because it runs on the host network, the proxy needs a way to access the server itself. The following entry provides that`host.docker.internal:host-gateway`: It makes the server's address accessible`host.docker.internal` within the proxy container under the name .

**Traefik:** Add the following to `__ROOT__/traefik/compose.yaml`the service`traefik`:

```yaml
    extra_hosts:
      - host.docker.internal:host-gateway
```

Then Home Assistant receives the  labels`compose.yaml`, but **not the** `networks:`. Traefik detects the host network and forwards `host.docker.internal`the request to :

```yaml
    labels:
      - traefik.enable=true
      - traefik.http.routers.home-assistant.rule=Host(`home.__DOMAIN__`)
      - traefik.http.routers.home-assistant.entrypoints=websecure
      - traefik.http.routers.home-assistant.tls.certresolver=le
      - traefik.http.services.home-assistant.loadbalancer.server.port=8123
```

**Caddy:** Add the following as`extra_hosts` shown above and`__ROOT__/caddy/compose.yaml` redirect in the Caddyfile:

```
home.__DOMAIN__ {
  reverse_proxy host.docker.internal:8123
}
```

**Nginx Proxy Manager:** `home.__DOMAIN__`Create a proxy host with the domain. For the "Forward Host," enter the IP address of your home network server here`__SERVER_IP__`, and for the "Port," enter `8123`. Enable **WebSockets support**; otherwise, the interface won't load.

Then restart the proxy (`docker compose up -d`in its folder) so that it applies the change.

Now all that's missing is the firewall. The proxy's requests come from the Docker network`__NETWORK__`, not from your home network. Read the address range for this network:

```bash
docker network inspect __NETWORK__ --format '{{range .IPAM.Config}}{{.Subnet}}{{end}}'
```

The output looks something like this: `172.18.0.0/16`. You should leave this section set`8123` to Port :

```bash
sudo ufw allow from 172.18.0.0/16 to any port 8123 proto tcp
```
</Step>

<Step title="Setting Up Trusted Proxies in Home Assistant">
If you try to access Home Assistant via the domain right now, you'll get a **400: Bad Request** error. This is intentional: Home Assistant does not accept requests from a proxy that you haven't explicitly trusted. Otherwise, any device could claim to be acting on behalf of another.

So open Home Assistant again directly via  `http://__SERVER_IP__:8123`and go to **Settings → System → Network**. In the **HTTP** **Server** section, enable **“Trust X-Forwarded-For”** and enter the address range you just noted under **“Trusted proxies”**—for example, `172.18.0.0/16`. When you save, Home Assistant will restart. You must then confirm the new settings within five minutes; otherwise, they will be reset.

The names of the options may be slightly different in the German interface. The [documentation on HTTP integration](https://www.home-assistant.io/integrations/http/) describes them in detail.

<Callout title="Older versions: configuration.yaml">
Up through version 2026.7, these settings were located in the file  `configuration.yaml`in the folder`__DATA(home-assistant)__/config`. In many online guides, you'll still find this block:

```yaml
http:
  use_x_forwarded_for: true
  trusted_proxies:
    - 172.18.0.0/16
```

Starting with version 2026.8, Home Assistant imports an existing block into the interface during an update and prompts you to delete it from the file afterward under **Settings → System → Repairs**.
</Callout>

Home Assistant should`https://home.__DOMAIN__` now load at . If the proxy reports instead`502 Bad Gateway`, it `8123`cannot reach port . Most often, the firewall rule you just set up is missing; see below for more on ["Bad Gateway" and "404" errors from the proxy](/en/wiki/bad-gateway/). Finally, enter the address as the Home Assistant URL under **Settings → System → Network**, and use it in the Companion app on your phone as well. You `8123`can then delete the rule for your home network on port  once you no longer need direct access (`sudo ufw status numbered`, then `sudo ufw delete <Nummer>`).

If you want to access Home Assistant while on the go, the same considerations apply as with any other service: A [VPN](/en/setup/vpn-wireguard/) is the most secure option. Login protection such as Tinyauth for Home Assistant is not compatible with the Companion app.
</Step>

<Step title="Pass along the USB flash drive for Zigbee (optional)">
Many smart home devices use **Zigbee**, an energy-efficient wireless standard. To use them, you'll need a USB dongle that acts as a wireless receiver—known as a coordinator. You'll need to connect it directly to the container.

It's best to connect the USB flash drive using a short USB extension cable. If you connect it directly to the server, the interference from USB 3 ports and hard drives will noticeably disrupt the wireless signal. Then look for the USB flash drive's fixed name:

```bash
ls -l /dev/serial/by-id/
```

Enter the path from `/dev/serial/by-id/`, not `/dev/ttyUSB0`. The number may change after a restart, but the name under  `by-id`remains the same. `home-assistant`Enter it in the  `compose.yaml`under ; the name here is just an example:

```yaml
    devices:
      - /dev/serial/by-id/usb-Example_Zigbee_Stick_1234-if00-port0:/dev/ttyUSB0
```

Next, set`docker compose up -d` up the **Zigbee Home Automation (ZHA)** integration in Home Assistant and specify `/dev/ttyUSB0`it as a device. The alternative, Zigbee2MQTT, requires an additional MQTT broker and then runs as its own container.

If you're using HAOS in a Proxmox VM, you can instead pass the USB stick to the VM within Proxmox: in the VM, go to **Hardware → Add → USB Device**, preferably using the manufacturer and device IDs. Home Assistant will usually detect it on its own.
</Step>

<Step title="Backup">
Everything that makes Home Assistant what it is is found in`__DATA(home-assistant)__/config`: Settings, Automations, Devices, and the database with the history. With [borgmatic](/en/setup/backups-borgmatic/), the folder is automatically included because it is located`__ROOT__` under .

The database is an SQLite file that is constantly being written to. Therefore, be sure to set up the built-in automatic backups under **Settings → System → Backups**. Home Assistant stores these backups in a consistent state in the configuration folder, and borgmatic also backs them up. Make a note of the key that Home Assistant displays in your password manager. Without it, the backups cannot be restored.
</Step>

</Steps>
