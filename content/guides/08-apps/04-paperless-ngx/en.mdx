Paperless-ngx is a document archive. You give it a scan or a PDF, it recognizes the text in it with **OCR** (optical character recognition, text recognition on images), creates a searchable version and sorts the document by sender, type and tags. Afterwards you find the utility bill from three years ago in seconds instead of leafing through binders on the shelf.

Because very personal papers quickly end up in Paperless, a clean backup belongs to it from the start. That's why it's the last step of this guide, and it isn't optional.

<Steps>

<Step title="Create the folders">
Paperless consists of three containers: the application itself, a PostgreSQL database and Redis (here in the compatible variant Valkey) as a queue for tasks like text recognition.

Two folders are especially important for you:

- **consume**: the inbox. Paperless imports everything that lands here and then removes it from the folder.
- **export**: the target for the export you'll use for the backup later.

Create both as your user before the first start, so you can write into them yourself:

```bash
mkdir -p __ROOT__/paperless-ngx __DATA(paperless-ngx)__/consume __DATA(paperless-ngx)__/export
```
</Step>

<Step title="Write compose.yaml and .env">
<ServiceFiles id="paperless-ngx" />

A few settings in the template, briefly explained:

- `PAPERLESS_OCR_LANGUAGE=deu+eng` recognizes German and English text. The image ships with both languages. Every additional language makes text recognition slower, so only use what you need; for English documents only, `eng` is enough.
- `USERMAP_UID` and `USERMAP_GID` define which user ID Paperless works with. Set them to your own (`id` shows it); then the files in `consume` and `export` belong to you as well.
- `PAPERLESS_URL` is the address you open Paperless at. For security reasons, Paperless then only accepts requests to this address. If you open it under another address, you get an error 400 or a CSRF message when logging in.
- `PAPERLESS_SECRET_KEY` signs sessions. The value must stay secret and must not change after the first start, otherwise you're logged out everywhere.
</Step>

<Step title="Start and create the admin">
```bash
cd __ROOT__/paperless-ngx
docker compose up -d
docker compose logs -f paperless-ngx
```

On the first start, Paperless sets up the database. That takes a minute or two. As soon as the log calms down, create the first user. It gets all rights:

```bash
docker compose exec paperless-ngx createsuperuser
```

You'll be asked for a user name, email address and password. Then log in in the browser. You create more accounts, for your partner for example, in the interface under **Users & Groups**. Don't give them admin rights if they should only file documents.
</Step>

<Step title="Get documents in">
There are several ways, and you can combine them freely:

- **Upload in the browser:** drag files onto the start page. That works on your phone too, where the camera becomes your scanner.
- **consume folder:** every file that lands in `__DATA(paperless-ngx)__/consume` gets imported. That's the way for scanners and for everything that should happen automatically.
- **Email:** Paperless can fetch a mailbox and import attachments. You set this up under **Mail** in the interface.

Paperless processes PDFs, images like JPG and PNG, and plain text files. For scanned documents, 300 dpi and grayscale are worth it. That's enough for good text recognition and keeps the files small.

On import, the original is kept unchanged. Next to it, Paperless creates an **archive PDF** with the recognized text. With the search field at the top, you can then find every word in your documents.
</Step>

<Step title="Connect scanner and PC via Samba (optional)">
Most network scanners and multifunction devices can scan directly into a Windows share ("Scan to SMB" or "Scan to Folder"). You provide such a share with **Samba**, the Windows file sharing service for Linux. Samba runs directly on the server here, not in the container.

```bash
sudo apt install samba
```

Append a section for the inbox at the end of `/etc/samba/smb.conf`. `__USER__` is your Linux user from "My setup":

```ini
[paperless]
   path = __DATA(paperless-ngx)__/consume
   valid users = __USER__
   writable = yes
   browseable = yes
   create mask = 0664
   directory mask = 0775
```

Samba has its own passwords. Set one for your user and reload the configuration:

```bash
sudo smbpasswd -a $USER
sudo systemctl restart smbd
```

The firewall must let Samba through from the home network, but not from the internet:

```bash
sudo ufw allow from 192.168.1.0/24 to any port 445 proto tcp
```

Adjust the network to yours. Current devices only need port 445. In the scanner, you then enter `\\<server-IP>\paperless` as the target, with the user and Samba password. On your PC, open the same address in Explorer and simply drag files in.

<Callout title="Old scanners and SMB1">
Some older devices only support SMB1, an outdated and insecure version of the protocol. Current Samba rightly turns it off. A firmware update, "Scan to FTP" or "Scan to Email" is then often the better way, instead of turning SMB1 back on.
</Callout>
</Step>

<Step title="Get organized: tags, correspondents, document types">
Paperless sorts documents with three kinds of attributes:

| Attribute | Example | Question |
|---|---|---|
| **Correspondent** | Utility company, health insurer, employer | Who is it from? |
| **Document type** | Invoice, contract, notice | What is it? |
| **Tag** | Taxes 2026, car, apartment | What does it belong to? |

A document has one correspondent and one type, but any number of tags. Only create a handful at first and add more when something is missing while filing.

For automatic assignment, every attribute has a **matching algorithm**. The default, **Auto**, learns from your previous assignments. So if you sort the first twenty or thirty documents by hand, Paperless will usually suggest the right thing itself afterwards. For cases with a clear marker, a customer number for example, you can set a fixed word instead. **Workflows** offer even more automation, for example giving every document from the scanner an "Inbox" tag. Everything else is in the [Paperless docs on usage](https://docs.paperless-ngx.com/usage/).
</Step>

<Step title="Backup: database dump and export">
For Paperless, you need two things in the backup:

1. **A dump of the database.** It holds all assignments, tags and notes. The files in `media` alone aren't enough, because without the database they're just a pile of PDFs.
2. **An export with the `document_exporter`.** It writes all documents plus a `manifest.json` with all metadata into the `export` folder. That's the official, version-independent format you use to restore Paperless cleanly on a new server or after a big update.

borgmatic does both before every backup. If you've set up [Backups with borgmatic](/en/setup/backups-borgmatic/), add these lines to the `commands:` block:

```yaml
commands:
    - before: action
      when: [create]
      run:
          # Paperless-ngx: database dump and document export
          - mkdir -p -m 700 __DATA(paperless-ngx)__/db-dump
          - docker compose -f __ROOT__/paperless-ngx/compose.yaml exec -T db pg_dump -U paperless -d paperless > __DATA(paperless-ngx)__/db-dump/paperless.sql
          - docker compose -f __ROOT__/paperless-ngx/compose.yaml exec -T paperless-ngx document_exporter ../export --delete
```

`../export` is the path inside the container; it points to your `export` folder. Next time, the exporter only writes new and changed files, and `--delete` removes files of deleted documents. If you already have a `commands:` block, the lines go in there as well. If you'd rather click the configuration together, use the [borgmatic config](/en/tools/borgmatic-config/) tool.

Then check with `sudo borgmatic config validate` and run a backup once. If `paperless.sql` and a `manifest.json` are in your folders afterwards, everything fits. [Testing restores](/en/setup/testing-restores/) shows how to get back a dump and individual files.

<Callout type="warning" title="Sensitive data">
Paperless holds bank statements, contracts and ID copies. So the backup must be encrypted, which borgmatic takes care of. And Paperless itself shouldn't hang openly on the internet: use a [VPN](/en/setup/vpn-wireguard/), or at least put [Tinyauth](/en/setup/tinyauth/) or [Pocket ID](/en/setup/pocket-id/) in front.
</Callout>
</Step>

</Steps>
